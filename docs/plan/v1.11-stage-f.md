## 0. 派发前侦察——三处必须偏离原方案的地方（主程已核实，不再讨论）

### ① Tauri 侧没有 keychain，也没有 http 插件

`src-tauri/Cargo.toml` 只有 `tauri-plugin-log = "2"`；`src-tauri/tauri.conf.json` 没有 http
allowlist / capabilities。**因此：**

- **F1 的「Key 存 Tauri 系统 Keychain」改为**：默认**会话内有效、不落盘**（零明文、也零"假加密"）；
  可选「记住我的 Key」走 **WebCrypto AES-GCM + PBKDF2(家长口令)**，只落密文 + salt + iv。
  真 Keychain 需新增 Rust 插件（`tauri-plugin-keychain` / `stronghold`）+ 能力配置 + 重新打包 → **单开任务，不进 F1**。
- **F2 的「WebDAV 直连」**：客户端用原生 `fetch` 实现并可单测（mock），**但 WebView 内的跨域
  受限**——PWA 模式必被 CORS 挡，Tauri 模式真机直连大概率需要 `tauri-plugin-http` +
  capabilities 配置。裁定：**通道代码、合并、UI 照做**，端到端真机直连列为**受限项**并在 UI
  上如实提示失败原因；需要 Rust 插件时单开任务。
- **F2 通道 B（局域网 mDNS/http server）确认为选做并延后**（原方案已标注可延后，且它同样
  依赖 Rust 侧 http server 能力）。

### ② 新 settings 键有门禁

`npm run check:settings-keys` = `vitest run tests/settings-keys.test.ts`。任何新增 settings 键
必须登记，且按档案分片的键要走 `settingsScope.ts` 的 `scopedKey()` / `classifyKey()`
（8 个受管键 + 27 个访问点既有约束）。**AI Key / WebDAV 配置属设备级（家长资产），
不按 profileId 分片**，登记时要按"设备级键"处理，别误用 scopedKey。

| 用途 | 现成入口 |

## F1 · 错题 AI 启发式讲评（P0）

**目标**：错题卡「💡 启发一下」→ AI 给**启发思路而非答案**的 Hint。

**架构约束**：多引擎（DeepSeek 云 API 优先 → 本地 Ollama `localhost:11434` 兜底 → 静态解析再兜底）；
零新依赖（原生 `fetch` + SSE，不用 openai SDK / axios）；Prompt 构建抽成纯函数可单测；
支持 `AbortController` 中断。

**分层**：
1. `src/core/ai/prompt.ts`（纯函数）：按错题内容 / 正确答案 / 错因 `mistakeCause`
   （`knowledge` / `careless` / `timeout` / `misread` 四值）组装 System/User Prompt；
   **限字数 + 屏蔽敏感词 + 注入防御**（题目文本是外部内容，必须清除"忽略以上指令"类模式）。
   ⚠️ **主程把关点**：Prompt 定稿必须人工过一遍，导向必须是"启发"不是"代做"（不直接给答案）。
2. `src/core/ai/aiClient.ts`：`deepseekClient`（流式 SSE）/ `ollamaClient`（探测 + 调用）/
   `router`（DeepSeek 优先，超时或失败降级 Ollama，再降级静态解析）。
3. `src/views/Mistakes.vue`：错题卡加「💡 启发一下」→ 抽屉（Drawer）+ 打字机流式展示；
   展示期间按钮 loading + 可中断。
4. `src/views/Settings.vue`：新增「🤖 AI 助手设置」AppCard（API Key、模型名）。
   **Key 存储按 0-①**：默认会话内有效；可选"记住"= WebCrypto 加密落 settings。

**验收**：单测覆盖 超时降级 / 流式解析 / Prompt 注入防御 / 中断；e2e 用 `page.route` mock
拦截断言打字机与降级提示；**反向验证：router 超时设 0 → 测试必须红**。

## F2 · 去中心化多端同步（P0，通道代码先行）

**目标**：WebDAV（坚果云 / Nextcloud）备份同步，**绝不接入中心服务器**。

**架构约束**：**只加传输通道，绝不重写合并**——复用 `planMerge` + `applyMergePlan` 的
"单调不减"；并发冲突以 `lastStudiedAt` 为基准，UI 上让家长选「保留本机 / 保留远端」。

**分层**：
1. `src/core/sync/webdavClient.ts`：原生 `fetch` 实现 PUT / GET / PROPFIND；
   URL 拼接纯函数可单测；失败分类（网络 / 401 / 404 / CORS）要能区分并给出人话提示。
2. `src/core/sync/syncManager.ts`：打包（复用 `buildBackupV2`）→ 上传
   `fls-backup-<profileId>.json` → 下载 → **走既有合并引擎** → 落库后刷新 store；
   **合并前置校验：防跨档案串数据**。
3. UI（**第二阶段，等 F1 的 Settings.vue 提交后**）：设置页「🔄 数据同步」AppCard
   （WebDAV 配置 + 手动上传/下载 + 上次同步时间）。
4. **口令存储按 0-①**，与 F1 同一套策略。

**验收**：单测（URL 拼接 / 合并前置校验 / mock fetch 的成功与失败分支）；
**反向验证：把合并改成"覆盖式" → 测试必须红**（证明守住了单调不减）。

## F3 · 内容生产工具与 W021–W023（P1）

**目标**：内容质量校验落工具链 + 极简导入向导。

1. 在 `scripts/validate.ts` / `lib/qualityChecks.ts` 补充三条警告（沿用既有码表约定）：

3. 内容预览（**第二阶段，等 F1/F2 的 .vue 改动落地后**）：导入向导里先弹
   「此包含 X 个知识点，其中 Y 个题干可能不合规（W023）」，允许强制导入。

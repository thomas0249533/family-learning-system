## §0 派发前侦察修正（与原方案相悖的事实）

派发前实测了工具链、Cargo 依赖面、DB schema、QuizEngine 契约。**五处必须改写**，否则代理会按错误前提施工。

### 修正一 · Rust 侧不是"加个 candle"就完事：工具链齐备，但依赖面是空的

- ✅ `cargo 1.98.1` / `rustc 1.98.1` 在；`src-tauri/target` 已 4.4G（曾成功构建）；`D:\study\app2026*.exe` 有 4 个历史产物 —— **构建链路是通的**。
- ✅ `~/.cargo/config.toml` 已配 tuna 镜像（crates 下载没问题）。
- ❌ `Cargo.toml` 只有 `tauri` + `tauri-plugin-log` + serde。**没有 reqwest、没有 sha2、没有任何 fs/dialog/http 插件**；`capabilities/default.json` 只有 `core:default`。

**裁定**：A2 的"一键下载到 AppData + 选本地 .gguf"不是"顺手加两个命令"，是三条新依赖链：
`reqwest`（流式下载 + 进度事件）、`sha2`（SHA-256 校验）、`tauri-plugin-dialog`（选文件路径）。
**最小权限原则**：模型落盘、路径解析、文件读取**全部在 Rust 侧完成**，前端只拿"状态 + 进度 + 错误码"，**不给前端开 fs 权限**（不给 `fs:allow-*`，capability 最多加 `dialog:allow-open`）。这样即使前端被 XSS，也读不到任意路径。

### 修正二 · `@tauri-apps/api` 根本不在依赖里 —— A3 的前提不成立

- `src/core/pwa/isTauri.ts` 文件头明写：*"package.json 无 @tauri-apps/api（仅 @tauri-apps/cli devDep），故不引入依赖，改用 Tauri 注入的全局变量探测"*。
- A3 要"`invoke` command + `event.listen` 收流式 chunk"，只有两条路：
  ① 手抄 `window.__TAURI_INTERNALS__` 内部协议（可跑，但无类型、Tauri 小版本升级会静默碎裂）；
  ② 加 `@tauri-apps/api@2`（官方一方包，与已装的 `@tauri-apps/cli` 同版本族，运行时几乎零体积）。

**裁定：加 `@tauri-apps/api@2`** —— 本项目的**第一条"非零依赖"裁决**，理由是"一方官方 + 不用它就得上内部协议"，与"不准引重型依赖（echarts 类）"的原始意图不冲突。
**隔离约束**：`@tauri-apps/api` 的 import **只准出现在 `src/core/ai/candle/ipc.ts` 一个文件**，且必须是"非 Tauri 环境直接短路返回 null"的惰性 import —— 保证 Web/PWA 构建与全部单测（Node 环境）完全不受影响。

### 修正三 · 断点续传的地基早已存在 —— 方案高估工作量，但漏掉一个迁移陷阱

- `examSessions` 表**已经有** `currentIndex` / `answers` / `questionIds` / `status:'ongoing'|'finished'`；`ExamPanel.vue` **已经有**"🔄 继续上次（x/y）"。
- `QuizEngine.vue` **已经有** `save-progress` 事件（`{ currentIndex, elapsedSeconds, examAnswers? }`）与 `initialAnswers` / `initialIndex` props（第 279-290 行）—— 考试模式的断点续传早就跑通了。
- 所以方案里的 `SessionRecord(topicId/currentIndex/answeredExerciseIds)` **是平行造概念**。

**裁定**：
1. **不新建平行概念**，直接落 **`topicSessions` 新表（db version 5）**，字段仿 `examSessions` 但按 `topicId` 归档、`packageId` 保留用于归属解析；
2. QuizEngine **对外契约不动**（已有 `save-progress` / `initialAnswers` / `initialIndex` 足够），答题卡作为 QuizEngine 内部新增 UI；
3. **迁移陷阱（方案完全没提）**：`tests/helpers/fakeDexie.ts` 与 `tests/fakeDexie-guard.test.ts` 会**逐字比对** `src/db/index.ts` 的索引清单。加 v5 必须同步三件事：①fakeDexie 加 `topicSessions` 表 + 索引 + 行校验；②guard 保留 v4 断言不变、**新增 v5 断言**；③**v5 行必须带非空 `profileId`**（否则 guard 第 6 条直接红）。
4. **备份口径裁决（必须显式钉住）**：`topicSessions` = **设备本地瞬态，不进 `bundleIO` 备份、不进 `planMerge` 合并**。理由：把"做到一半的练习"搬到另一台机器没有意义，反而会在那边弹"继续上次"。必须有测试断言"备份字段集合没变"，防止未来有人"顺手补全"而破坏合并单调性。

### 修正四 · Candle 真实推理无法在本机验证 —— 这条红线必须提前说清

- 本机没有 GGUF 模型（Qwen 0.5B 也有 300MB+），也不应该为了跑一次而在开发机上下 300MB。
- **因此 A1 的验收只能是**：`cargo build` 绿 + command 面可用 + 逐 token 流式事件 + 缺模型/OOM 的具体错误码 + 降级链反向验证（强制 candle 不可用 → 必须跳过它走 Ollama）。
- **真实推理（首字延迟 < 5s）必须由你在 16G 机器上手动做**：放模型 → 设置页显示"已就绪" → 生成一句中文。主程**不会假装跑过**，会交付一份"用户手动验收清单"。

### 修正五 · 打包形态：主交付走 `--no-bundle`，bundle 只做加分项

- 本仓历史可靠路径：`npx tauri build --no-bundle` → `src-tauri/target/release/app.exe` → 复制为 `D:\study\v2.0.0.exe`。
- NSIS/WiX 需要联网拉工具链，失败率高。**裁定**：主交付 = `--no-bundle` 的 exe（必须成功）；安装包（bundle）作为"网络允许则附加尝试"，失败不阻塞 v2.0 收官。

### 版本漂移（顺手修）

`package.json` = `1.12.0`，但 `src-tauri/Cargo.toml` 与 `tauri.conf.json` 都还停在 **`1.9.1`**（历史欠账）。C1 一并统一到 `2.0.0`。

## 轨道 A · 离线 AI（技术定稿）

**降级链**：`Candle（本地 GGUF）` → `Ollama（本机 HTTP）` → `DeepSeek（云）` → `规则引擎（静态解析）`
（注：原方案写的是 Candle→Ollama→Cloud→规则，与现有 `requestAiHint` 的 ollama→deepseek 顺序不同 → **A3 必须显式定义新顺序并单测钉住**，不能改坏既有 `requestAiHint` 的语义。）

**模型策略**：不塞进 exe；`AppData/<identifier>/models/*.gguf`；下载后 SHA-256 校验；选择本地文件走 dialog 拿路径、**读取与校验仍在 Rust**。

**流式**：`ai_chat_stream` command 起后台线程/async task，`emit("ai-stream-chunk", {id, delta})`，结束发 `ai-stream-done` / `ai-stream-error{code}`；前端按 `id` 过滤（防止并发两次请求串流）。

**错误码**：`no-model` / `model-corrupt` / `oom` / `decode-failed` / `not-tauri` / `aborted` —— 每个都必须有对应人话文案，且 `not-tauri` 必须静默降级（Web/PWA 用户不该看到 Rust 错误）。

**反向验证要求**：把"candle 可用"判定强制改 false → 断言 `failures[0].engine === 'candle' && reason === 'unavailable'` 且最终文本来自 ollama（测试替身）。

## 轨道 B · 断点续传（技术定稿）

**表**：`topicSessions`（db v5）
```
'' 不需要；索引：'++id, [profileId+topicId], profileId, packageId, updatedAt'
字段：id?, profileId, packageId, topicId, questionIds[], answers{exerciseId:{userAnswer,isCorrect}},
     currentIndex, totalCount, startedAt, updatedAt, status:'ongoing'|'finished'
```

**写入时机**：QuizEngine 的 `save-progress` → TopicDetail 累积（`answer` 事件补 `answers`）→ 去抖写库。
**恢复时机**：TopicDetail 挂载 → 查 `[profileId+topicId]` 且 `status==='ongoing'` → 弹窗"检测到上次未完成的练习，当前进度 40/80，是否继续？"（继续 / 从头开始）。
**腐坏兜底**：缺字段、索引错、JSON 坏、`questionIds` 与当前题目对不上 → **静默丢弃、从头开始**，绝不抛、绝不白屏（方案已要求，必须写成单测）。
**答题卡**：QuizEngine 右上角「📇 答题卡」→ 网格：正确/错误/未做；点已答可回看解析，点未答可跳转。
**备份**：不进 bundleIO / planMerge（见修正三第 4 条），有测试钉住。

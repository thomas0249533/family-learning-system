# V3.0 里程碑定义 · 「每日闭环」Daily Loop Complete

> 目标：把系统从「功能齐备的工具箱」升级为「有节奏、能自转的学习系统」。
> 达到本文件的验收线后再统一发版（用户明确：不按周发版，攒到里程碑一次发）。

---

## 一、里程碑的一句话定义（North Star）

> **一个四年级孩子可以连续两周自己打开 App、自己按顺序做完、不需要家长在旁边指挥；
> 家长每周只看一次报告，就能判断「哪里真会了、哪里在假装会、下周该练什么」。**

拆成三个可检验的问题：

| 问题 | 当前答案 | 里程碑要求 |
|---|---|---|
| 孩子打开 App 知道今天该干什么吗？ | 首页有三个「推荐区」，但不知道该点哪个、点几个算完 | 首页只有一个入口：**今天的学习（3 项 / 24 题 / 约 18 分钟）**，按顺序执行，完成即结束 |
| 题目难度会跟着孩子的水平走吗？ | 难度只是题面上的标签（`metadata.difficulty`），选题不看它 | 连对升阶、连错降阶，同一知识点内有可换挡的题 |
| 家长看到的是数据还是决策？ | 一堆统计图，需要自己解读 | 每个结论都带**可执行动作**（加练 / 跳过 / 降标 / 换包） |

## 二、能力现状盘点（做方案前先承认已有）

**已具备、且够用（不要重做）**

- 学习包导入 / ZIP / 图片资产 / 依赖聚合（`core/importer`）
- 六类题型判分 + 填空六通道 + 听写判分（`core/quiz`）
- FSRS 复习调度 + BKT 掌握度 + 三级错题（`core/review` `core/mastery` `core/mistake`）
- 专题练习断点续做（`topicSessions`）、考试模式、逐题反馈
- 成就 / 连续打卡 / 盲盒 / 周报卡（`core/motivation`）
- 家长端统计、报告 PDF、搜索、知识图谱、笔顺描红、词汇背记与整单元听写
- 备份 bundle 导入导出 + 合并（`core/backup` `core/merge`）
- AI 讲题三级降级：DeepSeek → Ollama → 静态解析（`core/ai`）
- WebDAV 传输层（自写 Rust command，**尚未接真实网盘端到端验证**）

**结构性缺口（本里程碑要补的）**

1. **没有"今天"这个概念**。有推荐、有到期列表，但没有「今天要做多少、按什么顺序、做到哪算完」。
2. **没有会话编排**。每个入口（复习页 / 错题页 / 单元页 / 专题）各自为战，跨入口不连贯，做完没有统一的结算。
3. **难度是死的**。87% 的题只标了「基础 / 提高 / 挑战」，选题逻辑从不读它。
4. **家长只能看，不能改**。看到「这单元没掌握」之后没有下一步动作。
5. **数据只在本地**。备份要手动导出；`cardCompletions`（手动完成标记）还不在备份契约里。
6. **无"为什么"**。错因分析停在「错了 3 次」，说不出错在概念、计算还是粗心。

## 三、里程碑范围（M1–M5，按依赖顺序）

### M1 · 今日任务队列（核心，其余都挂在它上面）

**产出**

- `src/core/plan/dailyPlan.ts`：**纯函数**编排器
  - 输入：到期复习项、未掌握错题、薄弱知识点、未学单元、每日目标、今日已完成量
  - 输出：`DailyPlan { date, target, items[], done }`，每项含 `kind / 来源 / 预计题量 / 预计分钟 / 理由文案`
  - 固定优先级：**到期复习 → 待攻克错题 → 薄弱点重练 → 新学（按单元顺序）**；同级内按「逾期天数 × 权重」排序
  - 目标裁剪：超出目标时截断而不是全塞（避免"今天要做 90 题"直接劝退）
- `src/core/plan/dailyProgress.ts`：今日完成量（题数 / 分钟），存 `settings` 的 `dailyPlan:<pid>`，跨页面读取
- 首页改版：唯一的「开始今天的学习」大按钮 + 进度环 + 队列预览（点开可看今天为什么是这 5 项）
- `src/core/session/learningSession.ts`：**统一会话**——把复习、错题、新学串在一条流里，`QuizEngine` 复用现有引擎，不新写答题器
- 结算页：今日总结（题数 / 正确率 / 掌握变化 / 连对）+ 明天预告（"明天有 6 张卡到期"）

**验收**

- 新档案 → 导入一个包 → 首页 0 次跳转进入任务流 → 全程只按「下一题 / 完成」，能走到结算
- 断网可用（不依赖任何 AI / 网络）
- `tests/daily-plan.test.ts` 覆盖：空数据 / 只有复习 / 只有新学 / 目标溢出 / 逾期排序 / 同日幂等

### M2 · 自适应难度

**产出**

- `src/core/plan/adaptive.ts`：换挡策略（纯函数）
  - 同一知识点连对 3 题 → 下一题优先同 KP 的「提高/挑战」；连错 2 题 → 降到「基础」或回退前置知识点
  - 换挡失败（该 KP 没有其它难度层）→ **原地不换挡**，不报错、不跳过
- 题库分层索引：`knowledgePointId → difficulty → questions[]`，构建在会话开始时一次
- 会话内插入"讲一讲"：连续错 2 次自动展开知识点内容 / AI 讲解（无 Key 时用静态解析）

**验收**

- 只有基础题 / 只有挑战题 / 难度分布不均三种题库都能跑完会话
- 换挡结果可断言（给固定作答序列 → 断言下一题难度）

### M3 · 家长可行动

**产出**

- 今日任务编辑：加/减项目、锁定某单元（"这周不学"）、设每日目标（题量或分钟）
- 每个诊断结论挂动作：`未掌握 → [加练 5 题] [看讲解] [标记已会]`
- 「错因归类」：把错题答案与标准答案做**确定性对比**（数字错位 / 漏单位 / 拼写差 1 字母 / 概念性空答案 / 未作答），给出可执行归因，不猜

**验收**

- 家长改目标 → 孩子端今日队列下一次刷新立刻反映
- 错因归类对已有错题本可批量跑，输出 <300ms（纯本地）

### M4 · 数据可信

**产出**

- 自动快照：每天首次启动写一份本地快照，保留 7 份，设置页可一键回滚（不需要网盘）
- `cardCompletions` 进备份契约（`Bundle` + 导出 + 导入 + 合并四处同步改）
- 换机迁移向导：导出 → 新机导入 → 自检报告（包 / 进度 / 错题 / 成就 / 标记 五项计数比对）
- WebDAV 实盘验证清单（需真实账号，坚果云免费额度够用）

**验收**

- 手动删库 → 用快照恢复 → 进度/错题/成就零丢失（脚本比对计数）
- 备份导出 → 清空 → 导入 → 自检报告全绿

**落地记录（已完成）**

| 项 | 位置 | 说明 |
|---|---|---|
| 自动快照 | `core/backup/autoSnapshot.ts` + `components/AutoSnapshotPanel.vue` | 设备级键 `backup:snapshots`，同日跳过；不进导出、不进跨设备合并（防自我嵌套） |
| 标记进契约 | `types.ts` / `bundleIO.ts` / `mergeCardCompletions.ts` / `applyMergePlan.ts` | **推翻了 `db/index.ts` 里 V1.4 的"不进备份"决定**（理由见该字段注释）；备份文件里字段**可选**，老备份照样能导 |
| 合并语义 | `core/merge/mergeCardCompletions.ts` | 纯并集，key=`kind\0packageId\0targetId`；幂等（第二遍导入零写入） |
| 自检报告 | `core/backup/migrationCheck.ts`（纯）+ `migrationCheckService.ts`（IO）+ `ImportPreview.vue` | 判据是"**不少于**"而非"相等"：合并是并集，在用的设备 `actual > expected` 属正常，只有 `less` 报警 |
| 守卫补齐 | `syncManager.guardRemoteBundles` | 行级 pid 校验新增 `cardCompletions` 一项（别人家的标记也不许混进来） |

**WebDAV 实盘验证清单**（需真实账号，坚果云免费额度够用；未做则本轮不宣称支持）

1. 两台设备填同一 URL + 账号 → 「测试连接」都应成功
2. A 设备产生进度 → 同步 → B 设备同步 → B 上看到同样的进度条与错题数
3. B 设备改主题 → 同步 → A 同步 → 主题跟着变（全局键走 `globalsFromV2`）
4. A 删除一个错题 → 同步 → B 同步 → **B 不会把它救回来**（单调不减）
5. 故意用另一端被别家占用/改写过的文件 → 应报 `cross-profile` 而不是静默多出一个档案

**这一步抓到的两个真 bug（都是 e2e 才看得见的）**

1. **导入备份后今日页不重排**（本轮引入的接缝漏洞）：M1 的队列是当天冻结的，
   而失效动作原先只挂在「导入学习包」（`importService.afterPackagesChanged`）上，
   **备份导入这一路漏了**。症状是"导入了但今天没任务"，没有任何报错。
   修法：把失效下沉到 `core/backup/importOrchestrator.executeImport`
   （所有导入/恢复的唯一入口）。

2. **离开设置页整页空白**（历史 bug，V3.0 前就存在）：路由出口是
   `<transition mode="out-in">`，`out-in` 要等旧页面离场结束才挂新页面。
   实测从设置页点侧边栏去任何一页，离场状态机永远不结束 ——
   路由已切换、外壳正常、`<main>` 里只剩 `<!---->`、等 8 秒不变、**控制台无任何报错**。
   用户观感是"点一下侧边栏整页白掉，只能刷新"。
   修法：去掉 `mode="out-in"`（两页短暂交叉淡出 200ms，视觉更连贯），
   并显式 `:duration="200"` 让 Vue 不必猜过渡何时结束；
   新增 `tests/e2e/page-transition.spec.ts` 守这条回归。

## 四、明确不做（本里程碑内）

| 不做 | 理由 |
|---|---|
| 新内容包（五上 / 语文四下词汇） | 用户明确「还没到下学期，不着急」 |
| FSRS 升级（ts-fsrs 6.x） | 需完整复习历史 + Node≥24，收益不抵风险 |
| 云账号 / 多用户协作 | 与「家庭自用」定位冲突 |
| AI 自动出题 | 依赖外部 Key，且离线不可用；当前价值低于 M1/M3 |
| 便携包 / 周更发版 | 用户已裁决 |

## 五、执行顺序与发版判定

```
M1（今日闭环）──┬─→ M2（自适应，挂在会话内）
                └─→ M3（家长动作，依赖 M1 的 plan 数据结构）
M4（数据可信）可并行，独立于 M1–M3
M5 收尾
```

**发版判定（建议写进流程）**：M1 + M4 完成即可发一个可用版本（2.13.0）；
M2 + M3 + M5 完成再发 **3.0.0** 作为里程碑版本。
若用户希望一次发到位，则全部完成后再升 3.0.0。

## 六、风险与取舍

- **首页改版是破坏性改动**：现有「今日复习 / 最需要复习 / 今日推荐」三区要合并成队列 + 可展开详情，老用户（本机）应保留"查看全部推荐"入口，避免信息消失。
- **会话流 = 高风险重构**：`QuizEngine` 是 1000+ 行的既有组件，必须"复用它、不重写它"；跨模块串联放在外层 `learningSession`，用状态机推进，禁止把编排逻辑塞回 QuizEngine。
- **目标裁剪**可能让"想多练"的孩子觉得不过瘾：结算页给「再来一组」入口，不占今日目标，记为加练。

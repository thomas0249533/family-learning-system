## §0 派发前侦察修正（主程实测，与原方案相悖的三处 + 一处安全红线）

### 修正一（G1）：echarts 已在依赖里，且已有 token 喂色管道
- `package.json` 里 `echarts ^5.5.1` **本来就在**，`src/views/Home.vue` 已经在用它画图；
- `src/core/theme/useChartTheme.ts` 已实现「token → 图表色」的桥（`buildChartTheme(ThemeTokens)` / `useChartTheme()`），
  **图表用色不经过它就是色值漂移**（`check:hex` / `check:text-color` 门禁的延伸约束）。
- **裁定**：G1 复用 echarts `tree` 系列 + `useChartTheme`，不手写 SVG 力导向布局。
  原方案"不引入 ECharts"的本意是"零新增"，复用恰好零新增；手写布局工作量大、且难保证视觉基线确定性双跑一致。

### 修正二（G2）：markdown-it / html2canvas / jspdf 全部已在依赖
- `markdown-it ^14.1.0`（含 @types）、`html2canvas ^1.4.1`、`jspdf ^4.2.1` 都已安装；
- E3 已建 `src/core/report/`（`weeklyCard` / `pdfExporter` / `exportImages` / `canvasKit`）——
  诊断报告的"导出 PDF / 保存本地"**必须复用这条既有管道**，不许再写一份导出代码。
- **裁定**：报告渲染用 markdown-it（已有依赖），导出复用 `src/core/report/` 管道。

### 修正三（G3）：手写 QR 编码器不可行，改 vendor 公认实现
- 正确的 QR 编码含 Reed-Solomon 纠错、掩码评分、版本选择，绝不是 200 行能写对的；
- 更致命的是**反向验证做不到**：仓库里没有 QR 解码器，手写编码器的单测只能断言矩阵结构，
  断言不了"手机真扫得出来"——这违背本仓"不准跳过反向验证"的铁律。
- **裁定**：把 Project Nayuki 的 `qrcodegen`（MIT，单文件、纯函数、零依赖、TS 原版）
  vendor 到 `src/core/share/vendor/qrcodegen.ts`，**保留许可证头**。它不进 `package.json`，
  仍是"零新 npm 依赖"；"能扫出来"的正确性押在公认实现上。
  - vendor 文件是**生成物级别的存在**：不改它的内部实现、只允许裁剪到所需 API；
  - 解析端用 `BarcodeDetector` 特性检测，不可用则降级"后缀码手输"（方案原文已定，保留）。

### 安全红线（G3，方案原文未覆盖，必须执行）
二维码会被**拍照外传**——所以编码进 QR 的内容**绝对禁止包含 WebDAV 口令 / API Key / 任何密钥**。
载荷只允许：类型、包 id 与校验和、指向局域网地址或 WebDAV **地址+账号**（无口令）。
解析端防御：字段白名单 + 长度上限 + 协议白名单（`FamilyLearning://` / `https://` / `http://`），
解析结果**只走结构化对象，绝不进 `v-html` / `eval`**。

### 文件名修正（G3）
`PackageList.vue` 在 `src/views/learn/PackageList.vue`（不在 `src/views/` 根下）；
`ImportWizard.vue` 在 `src/views/settings/`。两文件均无人动，零重叠成立。

## 任务 G1 · 知识图谱与技能树（复用 echarts）

1. **纯函数层 `src/core/graph/buildGraphData.ts`**
   - 输入：包清单（`packages[]`，含 `knowledgePoints`，层级以 manifest 真实结构为准——
     KP 自身**没有** subject/unit 字段，学科来自包元数据，单元若存在则插入一层）；
   - 输出：`学科 → (单元) → 知识点` 树；每节点聚合状态 `unlearned / learning / review / mastered`；
   - **铁律**：状态判定必须复用 `src/core/mastery/` 的既有判据（`masterySummary.ts` / `masteryRules.ts`），
     **禁止就地另写一套公式**（掌握率口径统一是 V1.x 已裁决的既有纪律）。
2. **渲染层 `src/views/KnowledgeGraph.vue`**（新路由 `/graph`，lazy import 注册进 `src/core/router/index.ts`）
   - echarts `tree` 系列；节点色来自 `useChartTheme()` 的语义色映射，**组件内零硬编码色**；
   - 悬浮/点击 tooltip：知识点标题、错误次数、状态；空数据态用 `EmptyState` 基元。
3. **入口**：`Home.vue` 顶部加「🌳 技能树」按钮（跳 `/graph`）。
4. **验收**：`tests/graph-data.test.ts`（空数据 / 单根 / 多叉树拓扑 + 状态判定四态）；
   `tests/e2e/g1-graph-visual.spec.ts` 产 `knowledge-graph-light/dark.png`；重建被弄脏的 `home-*.png`。

## 任务 G2 · AI 批量错题诊断报告

1. **Prompt 纯函数 `src/core/ai/diagnosisPrompt.ts`**
   - 输入是**统计摘要**：错因计数、高频卡壳知识点（id+标题+错误次数）、时间范围；
     **绝不发送**：孩子姓名、档案 id、逐题题干原文、掌握度历史（比 F1 单题更严：这是批量外发）；
   - 口吻"专业导师"，输出 Markdown；统计条数与字符数双上限（超长截断有单测）。
2. **诊断引擎 `src/core/ai/diagnosis.ts`**
   - 复用 `aiClient.ts` 导出的 `streamDeepSeek` / `streamOllama`（二者已接受任意 system/user，可直接用）；
   - 降级路由仿 `requestAiHint` 的 `failures` 链（DeepSeek → Ollama → 本地规则引擎）；
     本地规则引擎 = 纯统计摘要（错因比例 + Top 卡壳点），**永不失败**；
   - 用户中断（`aborted`）不降级，直接终止。
3. **UI 层 `Parent.vue`**：「🧠 AI 学习诊断」卡片；生成中打字机流式 + 可中断；
   markdown-it 渲染（** sanitize 之后再进 DOM，禁 raw html**）；底部导出复用 `src/core/report/` 管道。
4. **验收**：`tests/ai-diagnosis.test.ts`（Prompt 上限/截断/隐私字段过滤、Mock 流式、降级链、aborted 不降级）；
   `tests/e2e/g2-diagnosis-visual.spec.ts`（Mock 接口断言流式渲染 + 降级文案 + 基线两张）；重建 `parent-*.png`。

## 任务 G3 · 跨设备二维码分发

1. **vendor `src/core/share/vendor/qrcodegen.ts`**（Nayuki MIT 原版，保留许可证头，只裁剪不重写）。
2. **`src/core/share/qrcode.ts`**：载荷组装（类型 + 包 id + 校验和 + 可选局域网/WebDAV 地址+账号，
   **无任何口令**）→ `FamilyLearning://import?...` 字符串 → QR 矩阵 → Canvas 渲染。
3. **`src/core/share/parser.ts`**：纯函数解析；字段白名单 + 长度上限 + 协议白名单；
   恶意字符串（脚本注入 / 超长 / 非法参数 / 伪协议）一律拒绝为结构化错误，绝不进 `v-html`。
4. **UI**：`learn/PackageList.vue` 加「分享」按钮（弹窗二维码）；
   `settings/ImportWizard.vue` 加「扫码导入」；`BarcodeDetector` 不可用时提示手输后缀码。
5. **验收**：`tests/share-qrcode.test.ts`（载荷往返、校验和、防御性解析全集）；
   `tests/e2e/g3-share-visual.spec.ts`（生成不崩溃 + 基线两张）；重建被弄脏的既有基线。

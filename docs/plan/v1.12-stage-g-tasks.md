## 通用纪律（写进每条线的 Prompt，违者打回）

1. **提交纪律**：只允许 path-whitelist 提交——`git commit -- <显式路径>`，**绝不裸 `git commit`**
   （Stage F 教训 `a6264e9`：裸提交会卷走别人暂存的文件）。**绝不准 `--no-verify`**；
   pre-commit 会自动跑 `typecheck:test`，红了解完再提交。
2. **零新 npm 依赖**：`package.json` 不许动。G3 的 vendor 文件是唯一例外（见方案 §0 修正三）。
3. **门禁自检**：新代码里的字符串常量**带冒号**的要过一遍 `npm run check:settings-keys`
   （它会扫 `'xxx:'` 形态字面量；小写驼峰开头+冒号结尾的会被拦）。改色只准走
   `useChartTheme()` / 语义 token，`check:hex` 与 `check:text-color` 不许红。
4. **反向验证**：每个"能工作"的断言必须有测试钉着；降级链必须能证明"确实降了级"。
5. **视觉基线**：新增 e2e spec 产自己的两张基线（浅/深），**确定性双跑一致**才算完成；
   自己弄脏的既有基线自己重建（跑对应 spec 更新 PNG 并逐张核对是预期内 diff）。
   e2e 用 `PW_TRACE=off npx playwright test <spec>`（安全软件拦 trace 的既有坑）。
6. **执行日志**：每线完成后向 `docs/memory/2026-10-23-v1.12-stage-g.md` **追加**一节
   （只追加不覆盖；提交时把日志文件带进自己的 whitelist）。
7. **日期口径**：凡是落库/展示的日期一律本地口径（`getFullYear/getMonth/getDate`），禁 `toISOString()`。

# V2.12.4 · 填空判分忽略末尾句末标点

**日期**：2026-10-29
**前版**：V2.12.3（同日发的三合一修复：判分兼容 + 四年级包内容修正 + 「全部完成」判定）

---

## 一句话

孩子在答案末尾顺手带的句号（`直角。` / `70。`）现在会被忽略，
不再因为一个句号被判错。

---

## 为什么又要发一版

V2.12.3 发完后的**全库体检**（`scripts/content/audit-4up-blank-answers.ts`）标出
49 条「可疑答案」，我逐条用真实作答去探测（不是只看答案串长什么样），
发现一个 V2.12.3 漏掉的同类缺陷：

```
kd4-33-2（special-math-4-up-kaodian.json）
  Q: 长方形和正方形也是平行四边形，特殊在四个角都是（　）。
  A: 直角
  孩子写「直角。」→ 判错 ❌
```

这和 V2.12.3 修的「答案带单位（`360 度`）被判错」是**同一类缺陷**：
孩子写的完全正确，被一个无语义的字符拖累。而「答案是 `30 度`」那个用户报的场景，
反过来也提醒了一件事：**凡是孩子会顺手写、而标准答案里没有的字符，都要考虑**。

标点是最典型的一种 —— 孩子在答案框里带个句号是极常见的书写习惯。

---

## 改动

`src/core/quiz/blank.ts` 的 `normalizeBlank` 增加第 8 步：

```ts
// ✅ 剥末尾句末标点（只剥末尾连续的一段；前面必须有内容）
.replace(/(.+)[。．.!?！？]+$/, '$1')
```

### 安全边界（为什么只剥末尾）

| 约束 | 理由 |
|---|---|
| **只剥末尾** | 答案**中间**的标点是语义的一部分 —— `淹没、淹死` 的顿号、`48 亿；60` 的分号。剥中间会把并列项拆坏 |
| **两侧对称** | 标准答案自带句号、孩子不带，同样判对 |
| **必须有前置内容** | 纯标点输入（`。` / `。。。`）剥完为空 → 判错，不放行空答案 |
| **不碰段数与位置** | `70,锐角。` 对 `70,锐角` 判对；`锐角,70。` 顺序错仍判错；`70。` 漏填一个空仍判错 |

### 与既有通道的关系

`normalizeBlank` 是**所有判分通道的公共前置**，所以这一改动自动惠及
严格路径 / 数组路径 / 空格通道 / 斜杠备选 / 单位通道 / 括号并列通道 ——
不需要在各通道里各写一遍。

## 顺带记下的体检发现

体检脚本标出的 49 条里，绝大多数是**内容侧的「可疑写法」而非真错**：

- **B 类（答案带单位且题干也出现单位）37 条** —— 这类**恰恰是单位通道要修的**，
  现在全部判对。例：`d45-09-x02`（答案 `6 条`，孩子写 `6` → 对）、
  `m4-u3-ex-012`（答案 `15174克`，孩子写 `15174` → 对）。
- **A 类（顿号并列 / 括号补充）17 条** —— 括号并列的已被括号通道覆盖；
  顿号并列的（如 `潮来前、潮来时、潮去后`）是**列举型**语义，
  孩子必须写全，内核无法也不该放宽，靠内容侧维持。
- **C 类（单空答案含空格）3 条** —— 如 `48 亿；60`，属正常书写。

**唯一剩下的真缺口就是这次的句号。**

> 教训：audit 标「可疑」不等于「错」，但必须**逐条用真实作答探测**，
> 否则「写对被判错」的最后一类就会漏过去。
> 探测脚本可复现：拿 `gradeBlank(childInput, standardAnswer)` 跑真实输入。

## A1b + A2 + A3 · 离线 AI 全链（批二 · 完成）

### 交付
- **A1b 推理**（`src-tauri/src/ai/inference.rs`）：`ai_chat_stream(window, id, prompt, system, maxNewTokens?, temperature?, topP?)` **立即返回**，生成跑在 `spawn_blocking`；逐 token `emit("ai-stream-chunk", {id, delta})`（`tokenizers::decode_stream` 处理 UTF-8 跨 token 边界，半个汉字不出字、下轮补齐），结束 `ai-stream-done{id}` / `ai-stream-error{id, code}`。ChatML 模板（`<|im_start|>` 系列）——Qwen Instruct 是在 ChatML 上微调的，裸拼"系统+问题"会被当成续写文章。参数默认 max_new_tokens=256 / temperature=0.7 / top_p=0.9，命令参数可覆盖。
- **取消与并发**：全局 `StreamRegistry = Mutex<HashMap<id, Arc<AtomicBool>>>`；`ai_chat_abort(id)` 置位，推理循环每 token 检查，置位即停并 emit done；同 id 重入先掐旧的，清理时 `Arc::ptr_eq` 只删自己那一格（否则会删掉后来者的取消标志）。
- **模型家族裁定**：从 GGUF 头 `general.architecture` 读 arch，`qwen2` → `quantized_qwen2::ModelWeights`、`qwen3` → `quantized_qwen3::ModelWeights`，两个都支持；tokenizer 用 `candle_core::quantized::tokenizer::TokenizerFromGguf`（`tokenizers::Tokenizer::from_gguf(&ct)`，0.11 里这个 trait 在 candle-core 不在 transformers）。
- **A2 模型管理**（`src-tauri/src/ai/models.rs`）：`ai_model_status`（路径/大小/sha256，**同 mtime+size 走缓存**）/ `ai_model_download(url, expectedSha256)`（reqwest 流式 + `ai-model-progress{received,total}` 每 256KB 或 120ms 节流 + 边下边算哈希，不符删文件返回 `model-corrupt`，sha 可留空但会算出实际值回填）/ `ai_model_pick`（**rfd 弹窗在 Rust**，spawn_blocking 里跑，复制进 models 目录不引用外部路径）/ `ai_model_remove`（.gguf + .part 半成品一起清）。**capabilities 未加任何权限**（依旧只有 `core:default`，rfd 不需要 capability）。
- **A3 前端路由**：`src/core/ai/candle/ipc.ts` 是**全仓唯一** `@tauri-apps/api` import 点（惰性动态 import + `isTauri()` 短路，非 Tauri 连模块求值都不发生）；`candleClient.ts` 包成可注入 `CandleIpc`，把 Rust 错误码映射到 `AiFailReason`（no-model→no-model、oom→oom、model-corrupt/decode-failed→bad-body）；`requestAiHintCandleFirst`：candle → ollama → deepseek → 规则，**既有 `requestAiHint` 的 deepseek→ollama 顺序一字未动**（有测试钉住）；`Mistakes.vue` 调用点换成新函数，UI 逻辑未动。
- **文案**：`AiEngine` 加 `'candle'`（label「本地离线 AI」）；`AiFailReason` 加 `unavailable`/`no-model`/`oom`，全部有"已改用其他方式"式人话。e2e `a-local-ai-visual.spec.ts`：浏览器开设置页必须渲染「🧠 本地离线 AI」卡片 + 「未安装」+ 降级说明 + **零 pageerror**（单测在 Node、构建不跑组件，这条是抓"Web 端直接 import 炸掉"的唯一门）。

### 判定与偏离
1. **reqwest 用 0.13 而不是 0.12**：tauri 2.11.6 自己依赖 reqwest 0.13.5（Cargo.lock 里本来就有），另起 0.12 会让同一套 hyper 编两遍（A1a 实测一次 release build 12 分钟）。`native-tls` + `stream` feature 0.13 同名同义，Windows 走 schannel 的裁定不变。
2. **三笔提交的切分与建议不同**：A2 的 Rust command 与 A1b 同在 `ai/` 模块树且共享 `mod.rs`/`lib.rs` 注册表，拆开要么制造一个不存在的中间态、要么第一笔编译不过。实际切法：①A1b+A2 全部 Rust → ②A3 前端路由+单测 → ③设置卡片+e2e+基线+记忆。三笔各自可构建。
3. **rfd 0.15 default-features=false**：Windows 后端不依赖任何 feature，关掉默认可避免引入 xdg-portal/async-std 一串无关依赖。
4. **`cargo build --release` 有一条 LNK4098 链接警告**（LIBCMT 与其他库冲突）——A1a 的干净构建没有，新增依赖引入。产物正常链接生成（app.exe 16.2MB），属警告非错误，留档待 C 线打包时观察。

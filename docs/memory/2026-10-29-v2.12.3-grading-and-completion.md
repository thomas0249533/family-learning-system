## 一、填空判分（`src/core/quiz/blank.ts`）

新增两条**纯增量**宽容通道（只在严格路径判错后才执行，绝不把 true 变 false）：

1. **数字 + 单位后缀容错**（`gradeBlankUnits`）
   - 答案 `360 度` ↔ 孩子 `360` → 判对。用户原话：「空外面有度这个单位，答案是 30 度，
     孩子填 30 就认为他答的是对的，然后系统给判的是错的」。
   - **只认「<数字><可选单位>」形态**：文字型答案完全不受影响。
   - 单位白名单 `MEASURE_UNITS`：`万`/`千`/`倍` 不是单位 → `15万` 不会蒙对 `15`；
     `85 千米/时` 的斜杠形式不在白名单 → 不走后缀兼容。
   - 单位不一致（`360 度` vs `360 米`）仍判错。
   - ⚠️ **单向**：只放行「答案带单位 → 用户不带」。反向（答案 `10000`、用户 `10000千克`）
     被既有护栏 `gradeBlank('10000千克','10000') === false` 钉死为 false，**不可放宽**。

2. **括号里的并列补充**（`gradeBlankParenAlternatives`）
   - 答案 `省（直辖市、自治区）` 填「省」「直辖市」「自治区」都判对。
   - 修的缺陷：单空路径只认「完全一致」与「去括号后一致」，孩子照着答案括号里的内容填反被判错。
   - 限定单空（多空由 `partsMatch` 的子串规则处理）；括号内项数 ≤ 6。

3. **连带修**：`splitCommaParts` 改**括号深度保护**。
   `normalizeBlank` 把顿号变逗号 → 答案 `6,省（直辖市、自治区）` 原先被切成 **3 段**
   （题目只有 2 个空），孩子填「直辖市」段数对不上而判错。
   校验脚本 `scripts/lib/qualityChecks.ts` 同步改同口径（新增 `splitTopLevelSegments`），
   W023 误报消除。

## 二、四年级学习包答案修正

**根因（用户没点破但更致命）**：每日一练 45 天里有 30+ 道「思维拓展」题被做成 **blank 填空题**，
答案却是一整段推导：

```
Q: …每箱售价140 元，这批苹果一共可以卖出多少元？
A: 140×30＝4200（元）。答：一共可以卖出4200 元
```

孩子写 `4200` 判错、写整段也判错 → **无论怎么答都是错的** → 那天**永远不可能「全部掌握」**
→ 只能把整天从头重做一遍。**这才是「很费时」的真正来源。**

改法（`scripts/content/fix-4up-open-blanks.ts`，显式映射表、幂等）：

- **A 类 · 有确定数值** → 答案改短答案（`4200元`），推导移进 `explanation`（16 道）
- **B 类 · 真开放**（多问/说明理由/预测/画图）→ `type: 'essay'` + 显式 `keyPoints`（22 道）
  - 主观题按得分点覆盖度判分（阈值 0.6），且**孩子/家长可手动纠正判定**
    —— 这正是用户说的「语文主观题可以自我审查判断是否答对」，数学现在也有。
  - `special-math-4-up-u3` 的 **examMode 关掉**：包内 6 道开放题在考试模式下既无逐题反馈
    也无自评按钮，判错后连参考答案都看不到。
- **C 类 · 顺序错位**：`d45-13-x02` 题干问「∠1 和∠2」，答案写「∠2＝50°，∠1＝130°」
  → 多空位置敏感，孩子按题干顺序写就判错 → 改为 `130°,50°`
- 语文：`淹没、淹死`（同义并列被当多空）→ `淹没（淹死）`；
  `无能、怯懦` → `无能（怯懦）`；`read-ex-058` 题干问 2 层答案给 3 段 → 改 2 段 + 第三层进解析；
  `u4-ex-005` 题干 2 空答案 1 元素 → `['想象','想象']`
- `kd4-40-1` `乘或者除以几` → `乘或除以相同的数`

### 得分点设计的经验
`gradeEssay` 的 `pointCovered` 要求**双向包含且双方长度 ≥ 2**：
- 单字符得分点（`8`）**永不命中** → 数字型答案要带单位（`8枚`）或改用片段；
- 结论词太脆（`够`/`够了`/`不够`）→ 优先用**数值**或**独特片段**（`八千零三万零四十`、`五千万`）；
- 2 个得分点时 ratio 0.6 实际要求**全中**（0.6×2=1.2>1）→ 想要宽松就用 1 个点或 3 个点。

## 三、每日打卡 / 专项练习「全部完成」（`src/core/learning/completion.ts`）

**根因是口径错位**：卡片状态只由 `progress.status` 聚合，而它判「已掌握」要**连对 3 次**
（知识点级的**复习**门槛）。但「这一天做完了没有」是**题目级**问题 —— 一道题做对一次就算做完了。

新判定：

> 卡片范围内所有知识点都学过 **且** 范围内没有「未掌握」的错题 → 判「已掌握」。

- 「都学过」→ 用户要的「当日题型全部掌握」
- 「错题都掌握」→ 用户要的「错题本里已掌握，标识就自动更新为全掌握」
  （错题在错题本连续答对 2 次即 `mastered`）

**红线**：不改 `progress.status`（那是 BKT/FSRS/掌握率/成就/弱项推荐的共同输入，
V2.4「虚拟 Good」已踩过这坑）。这是**纯 UI 层判定**。

手动通道：`cardCompletions` 表（**db v8 新增**），与 progress 完全隔离、可撤销。
- **不进备份、不进合并**（同 topicSessions / customSounds / packageAssets 边界）：
  真正的学习数据都在备份里，跨设备后自动判定照样判绿。
- `db.cardCompletions` 在单测的 fakeDexie（只实现 6 张表）里不存在 → **静默降级为空**
  （`cardCompletionsTable()` helper）。

UI：
- 单元卡上加「✓ 全完成」按钮（可撤销）+「还有 N 道待攻克」提示
- 包卡接入同一判定

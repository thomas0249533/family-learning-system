## 一、B1 · 消灭 `vue-tsc` 盲区

**根因**：主 `tsconfig.json` 只 `include: ["src/**/*"]`，`tests/` 的类型错误永远看不见，
只在运行期炸（V1.5 的 `RepeatRule` 就是这么进的库）。

**做法**：`tsconfig.test.json`（`extends` 主配置 + include 扩到 src 全部 + `tests/**/*.ts`）、
`npm run typecheck:test`、`verify` 链插入。主配置的 `strict` + `noUnusedLocals` +
`noUnusedParameters` 三件套决定了测试侧必然爆错。

**首跑 46 个错误 / 17 个文件**，分四类（这份分类本身就是复用价值）：

| 类 | 典型 | 修法 |
|---|---|---|
| ① 工厂用 `Record<string, unknown>` 收窄（最多） | `progressRow(over: Record<string, unknown>)` 把 `status` 退化成 `string`，返回值不可赋给 `ProgressRecord` | 改 `Partial<ProgressRecord>` / `Partial<MistakeRecord>` 并**标出返回类型** |
| ② 工厂缺标注导致字面量类型太窄 | `pkg(opts)` 无返回类型 → `manifest` 不可赋给 `LearningPackageRecord` | 标 `LearningPackageRecord`，补 `schemaVersion/grade/term`。**不动 src**（`packageType?` 别名本就存在） |
| ③ 真夹具缺陷（测试自己写错了） | `makeProgress` 缺 `profileId`（v4 必填）、自定义包夹具缺 `metered`、成就夹具缺 `repeatCount` | 补齐字段 |
| ④ 静默失效的指令/声明/开关 | 3 处 `@ts-expect-error` 挂在 `const FrozenDate: any` 上（`any` 不报错 → 指令失效）；`fakeDexie.transaction(mode,…)` 的 `mode` 未用；`settings-keys.scan` 的 `loadModule` 注入**从没接进三个递归函数** | 删指令留注释 / `_mode` / 删除静默失效的开关并写明"要加就一路传下去" |

**一处改了 src**：`mergeProgress.progressRank` 形参 `Pick<…>` 比实现更严
（实现第三段 `?? ''` 明确支持"两个时间戳都没有"）。**类型比实现更严也是失真** ——
调用方只能写 `as` 才能测那条分支，而 `as` 用惯后真该报错的地方也一起被盖住。
改为 `Partial<Pick<…>>`。

**门禁固化（不引入 husky / lint-staged）**：
- `scripts/git-hooks/pre-commit.mjs`（纯 Node，跑 `tokens:check → typecheck:test`，首条失败即停）；
- `scripts/git-hooks/pre-commit`（sh 垫片：定位 node，把"找不到 node"变成一句人话而不是
  `env: node: No such file`；找不到时**放行并告警** —— GUI 客户端 PATH 常常拿不到 node，
  硬拦会让人连改都提交不了）；
- `install.mjs`（覆盖前备份为 `.bak`）+ `npm run hooks:install`；
- **刻意不留跳过开关**（`--no-verify` 是使用者自己的权利，钩子不再开更隐蔽的口子）。

**坑（只在别人 clone 后炸）**：`core.autocrlf=true` 会把无扩展名的 `pre-commit` 转成 CRLF，
sh 带 CRLF 就是 `bad interpreter: /bin/sh^M`。两道防线：`.gitattributes` 加
`scripts/git-hooks/* text eol=lf`；`install.mjs` 复制时强制 `\r\n → \n`。

**反向验证**：`const wrong: number = 'rv-probe'` → `typecheck:test` EXIT=2 报 TS2322；
`git add` 后 `git commit` → 钩子先过 `tokens:check`(7.6s)、在 `typecheck:test` 处拦下 EXIT=1；
删除后 EXIT=0。

**给 `DesignSystem.vue` 加独立块 `data-ds="interaction-demo"`**（而不是往 8 个基元块里加节点）：
截图矩阵按 `.ds-block[data-ds]` 逐块出图，动那 8 块会让 22 张基线全部漂移。
实证：全量 e2e 后 `docs/screenshots/ds/*.png` 零变化。

**A6 冷却用例的两个关键选择**：
1. **失败注入**：备份带一条本机**没有**的进度行（预览 ready、守卫基线 `null`），
   预览定格后往同一个已存在的库 `add` 一行同 key → apply 事务内 L2 守卫必抛
   `stale-local-data`。不依赖时间戳比较、不依赖随机，第二次点击仍会失败。
2. **计 readwrite 事务数而不是数 toast**：toast 3 秒消失、与 2 秒冷却重叠，
   而"点完立刻断言仍 1 条"本来就通过（假断言）。事务计数是**同步**的 ——
   `db.transaction()` 在点击处理函数第一段同步代码里就调，`dispatchEvent` 一返回即可读，
   零 sleep、零轮询（唯一 wait 是刻意等窗口本身）。

**两个新坑（已写进 spec 注释）**：
1. **Dexie 4 在建库时就把 `db.transaction` 绑死了**（`createDBCore` 里
   `transaction: db.transaction.bind(db)`）。页面加载后再改 `IDBDatabase.prototype.transaction`
   对已打开的库完全无效（第一版静默数到 0）。必须 `addInitScript` 在页面脚本**之前**打补丁。
2. **"`:focus-visible` 鼠标点击不出环"在 Chromium+Windows 上不成立**（用键盘后更粘）。
   拿它当对照断言会在换内核时变假红 → 改成"未聚焦 / 键盘聚焦 / 失焦"三段对照。

**RV**：删 `AppButton` 的 `:disabled="disabled"` → 用例 1 红；注释冷却判断 →

## 四、B4 · 错误码人话 + 家长体验

**`src/core/errors/messages.ts`**（新）：`FriendlyError = { title, hint, action }`，
`action` 只描述**语义**（`id` + 文案）不写路由（core 一旦 `router.push` 就再也测不了）。
三条纪律：键是错误码值里不许出现错误码；title 说"发生了什么"、hint 说"现在怎么办"；
只有有确定动作的码才给按钮。

- `friendlyOf` **永不返回 null**（返回 null 时调用方漏写 `??` 会渲染成空白，比显示英文更糟）；
- `errorCodeOf` 先看 `code` 再退回 `name`（`DataCloneError` 是 DOMException，只有 `name`）；
- 三个码：`stale-local-data`（+重新选择文件）、`profile-limit`（+导出并删除旧档案）、
  `DataCloneError`（不给按钮 —— 家长能做的只有重试，给按钮是假动作）。

**导入向导**：第 1 步加原生 `<details>` 帮助面板（微信 4 步 / U 盘 3 步，含"文件多半在微信
缓存目录"的补救）；拒绝态**只有档案超限**给按钮；"详情"改「技术细节（反馈时可复制给开发者）」。

**档案上限**：`message.warning` 飘三秒 → 带动作的弹窗；`commitCreate` 的

**落地锚点**：本项目 router **没配 `scrollBehavior`**，`/settings#family-backup` 只是地址栏好看。

滚动容器可能是 AppShell 里那个 div 而不是 window）。

## 六、可复用的结论

1. **类型门禁的价值不在"修完的那 46 个错误"，而在第 ③ 类**：那些是测试自己写错了
   （缺 `profileId`、缺 `metered`、缺 `repeatCount`）—— 不打开类型检查，它们永远绿着骗人。
2. **工厂函数必须标返回类型**，且**不许用 `Record<string, unknown>` 接 patch**：
   它会把字面量联合擦成 `string`，一步就把类型安全让出去。
3. **"静默失效的开关"比"没有开关"更糟**（`loadModule`）：它让下一个人以为自己注入了什么。
4. **数"副作用"而不是数"提示"**：toast 有生命周期、会和被测窗口重叠，事务/写入次数是同步真身。
5. **el-toast / el-message 这类异步 UI 的断言，优先找同步可观测的量**（这次是事务计数）。
6. **新表面必须登记进门禁**，否则"能过但没人管"就等于随时可能悄悄变差。

# V1.5 续 · 自定义包支持 `"repeat": "weekly"`

> 日期：2026-10-20 · 承接 `2026-10-20-v1.5-repeat-weekly.md`
> 前情：那一版把 `repeat` 限定在**内置** `streak-7`，并明确划线"自定义包不支持"（§七.1）。
> 本次把这条线收掉 —— 但换了一种模式（`grow`），不是把 `hold` 开放给家长。

## 一、为什么不能直接把 `hold` 开放给家长

`hold` 的判据是**一个非单调谓词**（`holds(ctx, now) => boolean`）。内置 `streak-7` 能写，
因为代码里能读 `effectiveCurrent`。家长写的是 JSON，JSON 里没有"谓词"这种东西 ——
要让他们描述一个非单调谓词，只能上表达式（`eval` / 自研解析器），而 B3 的 D2 裁决
已经把"能跑代码的入口"钉死了（见 `customRule.ts` 文件头）。

所以 `counter` 型自定义卡换一个判据维度：不看"是否仍保持着"，看**增量**。

| mode | 判据 | 用在哪 | 数据需求 |
|---|---|---|---|
| `hold` | 布尔：这一周期是否仍然保持着那个状态 | 内置 `streak-7` | 只要一个周键锚点 |
| `grow` | 增量：这一周期是否又推进了 `step` 那么多 | 自定义 `counter` 卡 | 周键锚点 **+ 值游标** `repeatBase` |

`RepeatRule` 因此从 interface 变成**判别式联合**（`mode: 'hold' | 'grow'`）。
这一步顺带解决了一个隐患：原来 `holds` 是必填回调，任何"只填了 period"的半配置
在运行时表现为 `repeatCount` 静默不涨；判别式联合让填错组合在 `tsc` 阶段就红。

> 副作用（已处理）：`tests/repeat-weekly.test.ts` 里两处手写的
> `repeat: { period: 'weekly', holds }` 字面量缺 `mode`，运行期会掉进 grow 分支。
> 已补 `mode: 'hold'`。**`vue-tsc` 只检查 `src/**`，测试文件的类型错误没人拦** ——
> 这次是靠 vitest 跑红才发现的（见 §六）。

## 二、`grow` 的基线为什么是"相对上次计数"，不是"相对本周期开始"

若按周期开始记基线（每周一清零重记），**只在周末打开一次应用的家庭永远算不出增长**：
每次打开都正好是新周期的起点，`value - base` 恒为 0。

所以用**游标**：`UnlockedRecord.repeatBase` = 上一次计数时（或第一次观察时）的指标值。
增长会跨周累计，够一份 `step` 就记一次。

四条结算（顺序不能换）：

```
① repeatBase === undefined              → 只落游标，不计数        （升级 / 合并后丢失）
② lastRepeatPeriod >= 本周键            → 跳过                    （同周期幂等 + 时钟回拨）
③ value - base < step                   → 跳过，且**游标不前移**   （零头累计到下周期）
④ 否则 repeatCount + 1，锚点=本周键，游标前移到 value（一周最多一次）
```

- **③ 为什么要"不前移"**：前移就等于把这一周攒的零头丢掉。症状是"每周都进步一点点"
  的家庭永远拿不到第二次 —— 这恰好是最该被鼓励的那类节奏。
  反向验证过：把 ③ 改成"落游标再 continue"，
  `custom-pack-repeat.test.ts` 里「零头留着下周接着算」立刻变红。
- **④ 为什么游标要一次跳到当前值**：指标从 10 暴涨到 100（换了更大的题库 / 换档案）
  时，差值 90 会被反复换算成 9 次。一周只记一次 + 游标跳到底，
  等于"这次暴涨算一次，下次从 100 起算"。一周只涨一次也是这条的自然结果。

## 三、`step` 就是这张卡的 `target`，不给家长单独配

`step: rule.target`（在 `customPackDefs.toDef` 里写死）。

- `target` 已经是这张卡对"一次达成"的定义，重复一次自然就是"再完成一遍同样的量"；
- 多一个 knob 就多一个要解释、要校验、要防写错的字段，而它唯一多出来的表达能力
  （"每周只要动一点点就算又一次"）恰好会让「第 N 次」失去分量。

## 四、校验层的两条拒收

| 情况 | 错误码 | 理由 |
|---|---|---|
| `repeat` 不是白名单值（`daily` / `Weekly` / `1` / `null` / 对象…） | `E_REPEAT_PERIOD` | 猜或降级都会让家长以为配好了、实际没生效 |
| `manual-check` 带 `repeat` | `E_REPEAT_MANUAL` | 勾选态是 0/1，没有可累计的量 |

`E_REPEAT_MANUAL` 成立时**不重复报** `E_REPEAT_PERIOD` —— 错误码要指向真正的原因。

"勾选态每周重置一次"这条路没走：那会把 `customChecks` 从"一次性输入"
（`Record<packId::id, {at}>`）变成"按周的表"，是另一个数据结构，不在这一版。

## 五、存储与合并：游标**有意不合并**

| 字段 | 合并规则 | 为什么 |
|---|---|---|
| `repeatCount` | 取较大 | 次数是事实 |
| `lastRepeatPeriod` | 取较晚 | 幂等锚点，取早会重复计入同一周 |
| `repeatBase` | **不合并**（本机重新落基线） | 它是"本机看到过的最后一个值"，不是事实 |

搬运游标会造出"明明没做到却又 +1"这种没法解释的记录；不搬最多丢一周增量
（合并后第一次结算走 ① 重新落基线）。`dedupeUnlocked` 内部（同一次读里出现重复行）
则取**较大**游标 —— 宁可少记一次，不能虚涨。

`normalizeRepeatBase`：只认 ≥0 的有限数。负数 / `NaN` / 字符串一律当"没有游标"
→ 下次结算重新落基线，不会虚涨。

## 六、这次踩到的一个真问题：测试文件不在类型检查范围内

`tsconfig.json` 的 `include` 只有 `src/**`，`vue-tsc --noEmit` 碰不到 `tests/**`。
所以给 `RepeatRule` 加 `mode` 判别位时，`tests/repeat-weekly.test.ts` 里两处
手写字面量缺 `mode` **没有编译错误**，只在运行期掉进 grow 分支、一条用例变红：

```
× 自定义定义声明了 repeat 也能涨
  expected undefined to be 2
```

暂时不扩 `typecheck` 的范围（会让一批既有测试的类型欠账一次性暴露，属于另一件事），
但记在这里：**改公共类型时，测试文件要手动 `grep` 一遍字面量**。

## 八、没做的（明确划线）

1. **`daily` 周期**。`RepeatPeriod` 加一个 `'daily'`、`localDayKey` 当时周键即可，
   闸门逻辑一行不用改。但"每日之星"会让计数一个月涨到 30，印记失去分量，
   且 `customChecks` 的按周重置问题同样存在。要做得先回答"多少次之后这个数字就没意义了"。
2. **`hold` 型自定义卡**。需要家长描述非单调谓词 = 表达式沙箱，属独立课题。
3. **`repeatBase` 的备份往返语义**。导出里会带上它（`exportService` 导出的是原始
   `UnlockedRecord`），导入到另一台机器后会被当成"那台机器看到过的值"——
   与合并同一套理由：最多丢一周增量，不会虚涨，所以不特殊处理。

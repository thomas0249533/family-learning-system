## 二、本轮抓到的 3 个真 bug（都是「测试全绿」状态下潜伏的）

### 1. 家长端「连续天数」几乎恒为 0（最严重）

`Parent.vue` 拿 `expect.toISOString().slice(0,10)`（本地零点转 UTC = 前一天）去比
`lastStudiedAt.slice(0,10)`（UTC 日）。东八区下两边差一天 → 恒为 0。
同源缺陷另有 4 处：`reportGenerator` 的 `computeContinuousDays` / `computeRecent7Days`、
`Parent.vue` 的 `weekDays`、`Review.vue` 的分组键、`Report.vue` 的导出文件名。

修法：统一走 `localDayKey()`；`Parent.vue` 的 `continuousDays` 改为 `effectiveCurrent(streakState)`
（原来从 progress 日期集合二次推导，等于两套真相）。
守卫：`tests/date-discipline.test.ts`（7 条）静态扫 `src/**/*.{ts,vue}`，禁
`slice(0,10)` / `split('T')[0]` / `substring(0,10)` 三种 UTC 日键写法。

### 2. 补签后同屏成就概览不刷新（用户 C5 原话「徽章没亮」）

`Parent.vue` 的 `unlockedRecords` 是普通 ref，只在 `onMounted` 与档案切换时赋值；
`.ach-total-value` / `achByCategory` / `recentUnlocked` 全部派生自它。
`doRepair()` 里 `settle()` 之后没重读 → 提示说「新解锁」，同一屏 `N/27` 纹丝不动。

修法：`settle()` 之后、`message.success` 之前补 `unlockedRecords.value = await loadUnlocked()`。
落点很关键：**先 settle，再重读，再报文案** —— 否则「文案与数字同一帧」不成立。
全仓排查：只有 `Parent.vue` 持裸 ref 副本，其余视图都走 store 的响应式 `records`，
所以陈旧面仅此一处。

### 3. `reportGenerator.ts` 注释里的 UTC 字面量被自己新写的守卫扫到

写守卫时先把旧实现的写法写进注释，结果守卫精确点名自己。改注释表述即可
（「旧实现把 UTC 串截十位当日键」）。**写静态守卫时，注释里的反例字面量也会被扫**。

## 三、两个测试自身的坑（复用价值最高）

### 1. 负向 UI 断言在 SPA 里必然假绿

`await expect(locator).toHaveCount(0)` 在组件还没挂载完时**立刻满足** ——
「补签后卡片不该回来」在额度不扣的缺陷下依然通过（反向验证时抓到的）。

修法：先用**只在异步加载后才有内容**的锚点等挂载完成（家长端用高频错题区 `.top-item`），
再用 `expectNeverAppears()` 在 1.2s 窗口内持续采样。
**这个坑对全仓所有负向 UI 断言都成立。**

### 2. radio 的 `name` 必须按渲染实例唯一，不能只按数据 id

`Mistakes.vue` 的 `groupedMistakes` 会把**同一道错题推进多个分组**（一个题挂多个
`knowledgePointIds`），若 `name` 只用 `mistake.id`，12 个 radio 同组 →
键盘 ↓ 会跨分组跳焦点。分组视图必须 `'cause-' + group.kpId + '-' + m.id`。

## 四、实现细节备忘

### C5 补签额度不另开 settings 键

规格原本要求独立的 `studyStreakRepair` 键，实际并入 `studyStreak:<pid>` 行的
`repair?: { month, used }` 字段。原因：新登记一个 settings 键会同时撞三处门禁 ——
`tests/settings-keys.test.ts` 断言访问点恰 44、`profile-scope.test.ts` 断言
`PROFILE_SCOPED_KEYS` 长度恰 9、`mergeSettings.ts` 的 `RULES` 穷尽性编译失败。
且额度与打卡同一个 `put`，原子性更好。

`REPAIR_KEY` / `repairKey()` 仍导出但与 `streakKey()` 同键，签名保留形参便于将来拆行。

**`touchStudyDay` 必须显式带 `prev.repair`** —— 漏掉就等于打一次卡额度回满。

### `toPlain()` 会吃掉 undefined 键

本仓任何 `db.*.update(id, { k: undefined })` **静默无效**（`JSON.stringify` 先丢
undefined，patch 变 `{}`）。删键必须「读出行 → `delete` → `put`」。
注意 fakeDexie 的 update 是 spread 合并，**会保留**键 —— 与真库相反，
所以单测过不代表真库过。C1 的「取消打标」专门用 e2e 验了 reload 后仍是「未分类」。

### Dexie `setByKeyPath` 语义到不了库

`setByKeyPath` 内部确实 `delete obj[keyPath]`，但经 Dexie 的 patch 序列化后
undefined 已被丢弃，所以效果等同无效。C1 实测四场景的结论。

### ⚠️ 本次踩到的坑（必须记住）

**版本号要升四处，漏了后患很大。**
上一轮升 2.11.0 时只改了 `package.json` 与 `version.json`，**漏了 `src-tauri/Cargo.toml` 与 `src-tauri/tauri.conf.json`**。
后果：`npx tauri build` 打出的安装包是 `FamilyLearningSystem_2.10.0_x64-setup.exe`，
更新器读到的自身版本仍是 2.10.0 → 家庭端点「检查更新」永远判定"已是最新"，自动更新整条链路失效。

正确清单（5 处 + 2 个 lock）：
1. `package.json` version
2. `version.json` version + notes
3. `src-tauri/tauri.conf.json` version（决定安装包文件名与 updater 自身版本）
4. `src-tauri/Cargo.toml` version
5. `src-tauri/Cargo.lock` 里 `name = "app"` 的 version
6. `package-lock.json` 顶部两处 version
校验：构建日志必须出现 `Compiling app v<新版本>`。

**cpp path**：本机回话环境的 PATH 里没有 `~/.cargo/bin`，后台跑 `npx tauri build` 会报
`program not found`（cargo metadata）。必须先 `export PATH="$PATH:/c/Users/Administrator/.cargo/bin"`。

**git 协议被代理拦死**：`git fetch/push` 报 `schannel: failed to receive handshake`。走 REST API。
新建 `scripts/push-to-github.mjs`：本地无远端 base 对象，故不依赖 `git diff`，改为
**对比远端 tree（recursive）与本地 `ls-tree -r -z` 的 blob SHA** 求差异。
两个坑：① `ls-tree -r` 会把中文路径转义成 `"doc/1.8\345\220..."`，必须加 `-z`（NUL 分隔且不转义）；
② 上传 Release 资产时 `Accept` 必须是 `application/vnd.github+json`，只有 `Content-Type` 用 `application/octet-stream`，
写 `Accept: application/octet-stream` 会 415。

工具已入库：`push-to-github.mjs` / `publish-release.mjs` / `check-remote.mjs`。

## 二、学习包生产方法（可复用）

原始资料在 `content/资料/`（10 份 PDF，83MB，**已 gitignore 不入库**）。用 PyMuPDF 先探：
`scripts/content/probe-pdf.py` 统计每份的页数/字符数/无文本页数，据此分流：

| 类型 | 处理方式 |
|---|---|
| 文本可提取 | `page.get_text()` 直接切分；**答案不要信 PDF 答案区** |
| 扫描/图片页 | 每页 `get_pixmap(dpi=150)` 出图；要精读时**裁剪目标板块 + dpi=300**（同一图重复调用会被去重，裁剪改内容即可绕过） |

**答案可靠性铁律**：算术题的答案一律**程序计算**，不要采用 PDF 答案区。
《二上数学每日一练》的答案区排版错乱（Day01 的"脱式答案"里混着口算数值、章节标题重复），
但题面本身是标准算式，程序求值 1440 题 **0 失败**、0 错答案。

解析要点：
- 填空被折行：`(` 与 `)×3＝15` 分行 → 按"行尾无 ＝ 就与下一行拼接"合并
- `★` 标记剥掉后单独出"（需验算）"提示，别留在题面
- 反解填空 4 类正则：`()×3＝15` / `29＋()＝57` / `84－()＝41` / `20÷()＝5`（先统一全角→半角）
- 脱式解析用"逐层化简"：括号 → 乘除 → 加减，生成 `47＋32－22＝79－22＝57`

**答案页结构**：「含答案」的默写单常是 前 N 页空白练习 + 后 N 页同款已填答案，
只需读答案页即可拿到题目+答案（二上语文 16 页 = p1-8 练习、p9-16 答案，逐单元对应）。

**知识点 ID 不要手写 `::` 前缀**（W032）：包内 kp 用裸 ID（`kp-u1`），打包器自动加包前缀。
只有跨包引用（如 daily 包引用单元包 kp）才写 `unit-xxx::kp-yyy`。

生成脚本已入库：`scripts/content/gen-math2-daily.py`、`gen-cn2-vocab.py`。

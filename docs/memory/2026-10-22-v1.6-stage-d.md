## D1 的三条裁决（都写进了代码注释，别改回去）

1. **`attention` / `progress` 双模式**（`6ab2cc1`）：topic 卡走 attention（任一需复习→review），unit/package 卡走 progress（全掌握→mastered；无未学无学习中且有到期→review；否则 learning）。**"有未学就不催"**——整卡变红会让没练完的单元长期挂红，像告警而不是进度。
2. **状态底只用 `--badge-{tone}-bg`（= `-light`）+ `--{tone}-text`**：`/-soft$/` 被对比度门禁排除（`contrast-report.ts:153`），用 `-soft` 当卡底 = 静默绕过 AA。
3. **非状态语义色块不得染 tone**（`949a7b8`，`_card-status.scss` 硬约束 6）：`.unit-card-index` / `.topic-card-index` 原用 `$primary-light`（`#e7f3ed` ≈ `--success-light` `#e9f8ef`），在粉红/米黄状态卡上是第二种状态信号，连未学白卡都挂绿条。修法是**退回中性**（`--badge-neutral-bg` + `$text-main`），不是按状态染色——序号是序数，任何 tone 压在状态底上都是"第二种色调"。包卡的类型标签（绿"单元包"压粉底）**判定不改**：类型是全局四色约定，按进度变色更难理解。

## 门禁哲学（本轮最有价值的三条）

- **死键守卫**（`518f020`）：`MUST_PASS` 里登记一个匹配不到配对的键会**静默通过**——"登记了约束"≠"约束在生效"。逐组判定，死键必须为 0。
- **判决性断言**：守"X 不存在"的回归，不能用能容忍 X 的断言。D4 的 `expect.poll`（等 8s）永远抓不到"防抖被加回来"，必须换成抬笔后**一次直接读**。同理 D1 序号块，"四态一致"抓不到旧 bug（旧代码四态都是同一个绿），判决性的是"**不等于任何 `--badge-{tone}-bg` 的实测色值**"（用游离 div 挂 body 读 computed，与真实渲染同一条 var() 解析路径）。
- **反向验证的断言顺序决定证明力**：「一点就清+不改 aria-label」会先红在文案断言上，证明力弱；「只提前清空、确认态照常进入」才命中真正想守的那条。植入前想清楚红要落在哪一行。

## 视觉基线的两条铁律

1. **空库矩阵是结构性盲区**：`chromium.launch()` 全新 profile，`/learn` 只有 EmptyState——D1 的四态卡、D4 的工具栏在旧 16 张基线上一个像素都看不见，"零 diff"不是正确而是没覆盖。`learn-status-visual.spec.ts` 播种四态同屏（u3 第二个 KP 必须"需复习"而非"未学"，否则 progress 聚合退化成 learning，`is-review` 拍不到；一个包只能反演出一种状态，包卡四态要播 4 个包）。
2. **带进度数据的基线必须等成就 toast 稳态**：播种"已掌握"会解锁成就 → `.ach-toast`（position:fixed）正好压在状态角标上，消失时刻取决于真实计时器。解法是等它**连续 3000ms 不出现**，不是加大 `waitForTimeout`。确定性证据用 md5 双跑字节一致，别拿"git status 干净"当证据。

## E1：专项练习进度"丢失"的真相

**数据一行没丢。** 导出 `bundleIO.ts:172` 按 profileId 全量读、`mergeProgress` 单调不减、MergePlan 里全部正常落库。真正的缺口在备份格式之外：**v2 备份按设计不含 `packages`**（`types.ts:171`，PRD §P0-3b"学习包是设备级资产"）。专项包只存在于当初导入它的那台设备 → B 设备 `db.packages` 里没有它 → `/learn` 里这个包不出现 → "进度丢了"。这也解释了为什么只有专项包出事（内置单元包每台设备都从 content/ 装了）。

修法 = **把真相告诉家长**：`collectMissingPackageIds`（纯函数，只看行上的 packageId，不做归属推断）→ `ImportPreview.missingPackages` / `missingPackageRows` → 预览警告 `.import-missing` + 完成 toast。**不做任何数据过滤**，`resolveOutcome` 判序一行未动。反向验证②把 `mergeProgress` 改成"包不在就丢行"必须红——顺带证明**折叠阶段也不能丢行**（植入时漏了 `local.length>0` 守卫，红会落在 noop 而不是孤儿行上）。

遗留设计话题（未做，需产品裁决）：备份是否应携带学习包本体（体积换便利）。现状是"不再被静默"，家长仍需手动导入包。

## 环境坑（本轮新增/复确认）

- **并行代理共用工作区时，一方的 `git checkout --` 会打掉另一方的反向验证植入**——本轮出现过"植入后 6 passed"的假象，真相是植入被还回了、dev server 服务的是干净代码。植入前后都要确认"dev server 真的加载了变异代码"：`curl` 模块后 grep 标记，但 **esbuild 会剥注释**，要 grep 的是代码本身（如 `classList.toggle("ink-drawing", false)`）。
- 注释里写字面量色值会被 `check:hex` 拦（扫的是组件层文件的全文，包括注释）。色值证据统一放 `src/core/styles/_card-status.scss`（不在扫描范围）。
- pre-commit 的 typecheck:test 约 50s，**提交必须放后台**，前台 120s 超时会 SIGTERM 并留下 `.git/index.lock`。
- D4 防抖的教训：`onBeforeUnmount` 只覆盖路由切换，覆盖不了 reload/关标签页；而 `sessionStorage.setItem` 本来就是同步的——**没有需要合并的事件流就不要上防抖**，它只买了一扇丢数据的窗。

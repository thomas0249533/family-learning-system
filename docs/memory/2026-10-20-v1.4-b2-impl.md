## 本轮抓到的两个**真缺陷**（都不是"代码风格问题"）

### 1. `progressMerge` 分组键漏 `profileId`（B1 遗留，发布级）
`planProgressMerge()` 按 `(packageId, kpId)` 分组 → 两个档案学同一课时，B 的 upsert 复用 A 那行的
自增 id 直接 `update`，**A 的行被改写成 B 的数据、行数不变、零报错**。
入口 `ensureE1Migrated({orphanOnly:true})` 有 **3 个调用点**（导入包 / 恢复备份 / **每次启动一天一次**），
所以不是"导入时才犯"。修法：group key 加 `profileId`。
回归判据必须**逐字段比对本机那行不变**，只断行数会被"改写但行数没变"骗过。

### 2. `DataCloneError`：Vue 深层 `ref` 里的对象不能写进 IndexedDB
`previewImport()` 的结果放进 `ref` → `plan` 里上千行被逐个代理化 → Proxy 不能被 structured clone →
Dexie `put` 抛 `DataCloneError`，用户看到"未导入任何数据"。**单测永远测不到**，只有真机 UI 会踩。
- 源头：`shallowRef`（带行数组的对象不进深层响应式容器）；
- core 兜底：`executeImport` 写库前 `JSON.parse(JSON.stringify(plan))`；
- **JSON 往返是有损的**（`Date`→字符串、`Set/Map`→`{}`、`BigInt` 抛）。当前 db 时间字段全是 string
  所以无损，**将来给某表加 `Date` 必须改显式序列化**，否则日期被静默写成字符串（比它难查：不报错）。

## 与设计稿的三处修正（都已改文档）
1. **`unlockedAt` 不能用"空串最早"**：老设备 `''` 会永久抹掉真实日期，且与 `saveUnlocked()` 的
   `||` 优先非空冲突。改成「两边非空取更早 / 一边非空取非空侧 / 都空取空」。
2. **settings 值形状三处字段名是旧稿错的**：`dailyStats{date, questionCount, firstStudyAt, lastStudyAt}`
   （`firstStudyAt` 取 min）、`studyStreak{current, longest, lastDate}`、
   `discovery{chances, revealed, streakWithoutNew, lastGrantDay}`（后两者取 max）。
   **形状一律以 `src/core/motivation/*.ts` 真源为准，别照抄设计表。**
3. **`planMerge` 第 4 参 `remoteGlobals` 必填**：`Bundle` 只描述单档案，全局键无处可挂；
   "不传 = 静默不导全局键"不可接受，让编译期炸。

## 已裁决
- **`customChecks` 停用后保留**（PRD §8.2）。B3 必须同时把它登记进 `PROFILE_SCOPE_KEYS`，
  否则落进 `unknown` 分支：迁移多搬一份、导出被当未知键。
- **整行胜导致 `status` 回落：不加闸门**。加就是字段级合并，会造出「已掌握但明天到期」的行。
  AC-P2-12 守的是「旧备份不覆盖新进度」，不是"任何情况下掌握态只升"。
- **v1 备份不恢复全局键**（`fls:theme` / `audit`）：v1 的 `settings` 是未分类键值堆，
  照搬等于让一份可被手工改过的旧文件改写本机档案列表 = "换设备"语义混进"合并"。
- **`exportMistakes` 保持 v1 形状**：写成 v2 会被自己的路由判成损坏备份。

## e2e 三个坑（全是真机才暴露）
1. **`download.path()` 的文件会被清**：关掉发起下载的 context 后临时产物被删，稍后
   `setInputFiles(path)` 炸 ENOENT。必须**立刻 `readFile` 进内存**，用 buffer 上传。
2. **接收方必须先有同一个学习包**：备份不含 `packages`，B 机没装那个包时导进来的进度行是孤儿，
   `/parent` 的"已掌握"不会变 —— 这是场景不成立，不是合并失败。种子要种两个包。
3. **统计值带量词**（`"1 条"`）：断言用 `toContainText`，不要 `toHaveText('1')`。

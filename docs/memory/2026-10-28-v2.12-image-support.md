## 一、为什么之前做不了图形题

「数一数图中有几个三角形」离开图就是一句无法作答的话。而旧包格式只有文本字段，
所以看图写话包当时用「文字还原画面」绕过去。这次把整条图片链路补上。

## 二、架构：图存在哪里

**Blob 存 IndexedDB，不存 base64，不存 objectURL。**

- 内嵌 base64 到包 JSON 会让 `db.packages` 每次整行读写都把几十 MB 字符串解析一遍；
  且每道引用它的题都各带一份。
- objectURL 刷新即失效、必须手动 revoke，存 URL 等于存垃圾（与 `customSoundStore` 同一条理由）。

新增表（`db/index.ts` v7，纯新增、无 upgrade 钩子）：

```
packageAssets: '++id, [packageId+path], packageId'
{ packageId, path, mime, size, blob, createdAt }
```

- **包级，不是档案级**：兄弟档案共用同一份配图；不进备份、不进合并（与 `packages` 表同边界）。
- 主键 `[packageId+path]`：重复导入按同一路径覆盖，天然幂等。

## 三、路径三处约定（最容易踩的地方）

| 位置 | 形态 |
|---|---|
| 包 JSON `exercise.image` | `assets/q01.svg`（**包内相对路径，不含 packageId**） |
| ZIP 条目 | `packages/<packageId>/assets/q01.svg` |
| 源目录 | `content/<集合>/assets/<packageId>/q01.svg` |

包 JSON 不带 packageId，是为了换 packageId 后包仍然自洽（与 `rewriteIdsInPackage` 同思路）。
中间那层由 `build-lpkgset` 补上、由 `unzipPackageSet` 剥掉。

兼容：ZIP 根级 `assets/` 只在**单包**时归属该包；多包时直接报错，不猜。

## 四、题目要自带来源包

`normalizePackage` 现在给每道题写 `ex.packageId`。

原因：练习页的 `packageId` 来自**路由入口包**。依赖包的单元被合并进当前视图时，
用入口包去查图必然查不到 —— 表现就是"配图缺失"。代价约 40B/题（1440 题约 60KB）。

渲染侧统一写 `currentQuestion.packageId || props.packageId`（旧包没有该字段也能跑）。

## 五、渲染

- `src/components/QuestionImage.vue`：`[packageId, path]` → Blob → `createObjectURL`，
  **一个组件实例一个 URL，换图前 / 卸载时必 revoke**。加载失败降级为「配图缺失」占位
  （静默留白会让孩子以为自己看漏了，家长也发现不了内容缺陷）。
- `QuestionText` 增加可选 `packageId/image/imageAlt`，图片在文字之后渲染。
  **没有把图片做进 v-html**：那个组件唯一的安全保证就是"题干里一切都被转义成文本"。
- 接入点：`QuizEngine`（含 `ExamDetailItem` 交卷详情）、`ExamPanel`、`Mistakes`。

## 六、校验码（新增）

| 码 | 级别 | 含义 |
|---|---|---|
| E022 | error | 图片路径非法（`..` / 指向目录 / 扩展名不在白名单） |
| E023 | error | 图片在包里不存在（**必须 error**：存档一份空白题比报错更难查） |
| E024 | error | 单张 >2MB 或单包 >8MB |
| W034 | warn | 有图但缺 `imageAlt` |
| W035 | warn | 导入时某张图被拒（题仍正常，只是不显示图） |
| W036 | warn | 孤儿图（打进包却没题引用，通常意味着路径写错） |

`normalizePackage` 的 `assetPaths` 是可选 ctx：
**不提供时只校路径格式，不判存在性** —— 单独导入一个 `.json` 包（没有配套图）不能被判非法。

## 七、踩过的坑

1. **`ex.packageId` 不能省**。省了以后跨包题在导入校验时通过（图在题目所属包里）、
   渲染时失败（按入口包查），是典型的"上游看着对、下游静默空白"。
2. **几何计数的点集必须包含"图上标出来的点"**。一开始只收了线段端点 + 交点，
   结果"一条线上 4 个点"被算成 1 条线段（中间两个点根本不在点集里）。
   而这个错误答案 1 也是正整数，看着"像那么回事"。
3. **2 行 3 列的网格必须用正方形格**。原来格子是 100×80，数正方形算出来是 0 ——
   程序是对的（那个图里确实没有正方形），错的是图。**改图，不改答案**。
4. **SVG 固定画布留白过多**。420×320 画布画一条线，图上只有中间一条，答题页里
   却占了 250px 高，把选项挤到首屏外。改成按 bbox 裁 viewBox + `MIN_H=110` 兜底。
   注意：扁平图裁完后不能放大显示（线宽会变成 6~7px，像粗黑条）。
5. **`MathConcept` 是空壳**（只有一句"这里展示概念讲解"），`MathFormula` 里
   hardcode 了一组乘法分配律假数据，`MathLife` 也是占位。
   数学三个模块组件**没有一个真渲染知识点**。
   → 已修 `MathConcept`（照 `ChineseWriting` 用 `useKnowledgePoints`）。
   `MathFormula` / `MathLife` **仍是占位**，别把内容挂到 `formula` / `life` 上。
6. **`inferModuleType` 是 学科 × kp.type 映射**，没有命中时返回 null，
   `TopicDetail` 会走 fallback：`<AppCard :title="kp.title"><div v-html="content">`。
   所以想在数学里显示纯中文讲解，要么用 `concept`（已修好），要么让 type 落空。
   但 kp.type 有 schema 枚举（concept/formula/derivation/example/mistake/word/poem/grammar），
   不能随手写 `method`。
7. **旧版 App 导入含图包会静默丢图**：2.11.0 的 `unzipPackageSet` 不收集 assets、
   `QuestionText` 也没有图片支持。**含图包必须配合新版 App**，包侧无法自证（旧导入器不读新字段）。

## 九、巧数图形包（首个含图内容包）

`special-math-4-up-shape`，13 题 / 4 单元 / 13 张 SVG（共 9KB）：

| 单元 | 答案 | 方法 |
|---|---|---|
| 数线段 | 6, 10, 9 | n(n−1)/2；折线分开算 |
| 数角 | 6, 10 | 射线两两组合 |
| 数三角形 | 3, 6, 5, 8 | 按大小分类；底边线段数 |
| 数长方形/正方形 | 18, 36, 8, 14 | 横边×竖边；按边长分类 |

**答案全部由程序枚举**（图形 → 线段集合 → 点集 → 可见边 → 组合判定），
手写的只有干扰项。`tests/g4-shape-pack.test.ts` 里另有一张**人工另算**的期望表，
两边必须一致 —— 防止"改了图没更新答案"或"枚举本身有 bug"。

包内 `topic` **不写 modules**（校验会给 W031，不阻塞）：写了反而会命中占位的
`math.concept`，走 fallback 才有内容。

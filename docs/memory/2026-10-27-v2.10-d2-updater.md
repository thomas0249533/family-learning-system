# V2.10.0 D-2 自动更新 · 实施记录

## 决策（用户确认）
- 安装包格式：**NSIS**（installMode=passive，后台进度条）
- 保留**单文件 exe 便携版**（`--no-bundle` 产出 app2026-10-27b.exe）
- 更新包分发：**提交进仓库 `updates/<ver>/` 走 gitmirror**（国内最稳，绕开 jsdelivr 大文件限制）；`latest.json` 自身走 raw/jsdelivr/gitmirror 三镜像 endpoint

## 签名密钥（关键）
- 生成：`npx tauri signer generate --ci -w C:\Users\Administrator\.tauri\family-learning.key`
- 私钥：`C:\Users\Administrator\.tauri\family-learning.key`（**不进 git**，本机保管）
- 公钥：已写入 `tauri.conf.json` `plugins.updater.pubkey`
- 构建必须设 `TAURI_SIGNING_PRIVATE_KEY_PATH` 指向私钥，否则不生成 `.sig`、更新器校验失败
- 丢私钥 = 已装用户无法再收更新

## 工程改动落点
- `src-tauri/Cargo.toml`：deps 加 `tauri-plugin-updater = "2"`；`tauri-build` features 加 `["updater"]`
- `src-tauri/tauri.conf.json`：`bundle.createUpdaterArtifacts=true`、`bundle.targets=["nsis"]`、`plugins.updater{pubkey,endpoints[3],windows.installMode:"passive"}`
- `src-tauri/src/lib.rs`：builder 级 `.plugin(tauri_plugin_updater::Builder::new().build())`
- `src-tauri/capabilities/default.json`：加 `updater:default` + `process:default`
- 前端：`@tauri-apps/plugin-updater`+`plugin-process`；新增 `src/core/update/autoUpdater.ts`；`AppShell.vue` 改用 `runAutoUpdate`（真实插件 + D-1 兜底）

## 构建与发布流程（一次性命令）
1. `npm install`（装两插件）→ `npm run build`（前端校验，提前抓 TS 错）
2. 后台：`TAURI_SIGNING_PRIVATE_KEY_PATH=... CODEBUDDY_SAFE_DELETE_ENABLED=0 npx tauri build`（~52min，产出 NSIS+.sig）
3. `npx tauri build --no-bundle` → 复制 `target/release/app.exe` 为 `app2026-10-27b.exe`
4. `node gen-latest.mjs <ver>`：拷安装包到 `updates/<ver>/` + 写 `latest.json`（二进制 url=gitmirror）+ git add
5. `git commit` → API 推送（含 18MB 安装包 blob）
6. `node release-2.10.0.mjs <ver>`：建 tag+Release+上传资产（安装包/latest.json/便携exe）
   - 注：`cargo` 命令须在 `src-tauri/` 下；`npx tauri build` 在仓库根
   - gitmirror 大文件可达；raw 在国内常被墙，jsdelivr 对 >20MB 可能拒，故二进制走 gitmirror

## 首次过渡注意
2.9.0 是裸 exe 无更新器 → 2.10.0 须手动装一次 NSIS，之后才自动更新。便携 exe 也含更新器，但其自动更新会把 NSIS 装到默认位置（可能双份），建议日常用安装版。

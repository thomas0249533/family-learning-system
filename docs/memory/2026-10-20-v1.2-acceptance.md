## 推翻「不引入随机」时守住的四条线

裁决可以推翻，但原裁决**担心的东西**不能装作不存在：

1. **抽到的是线索，不是成就**。`drawDiscovery()` 只写 clue 到 `achievement:discovery`，**不碰任何解锁记录**；
   解锁仍只由 `achievements.ts` 的 `check(ctx)` 决定。e2e 断言"抽完 `.ach-seal` 仍为 0"守这条。
2. **一天一次、不累积**。`grantDailyChance` 跨天只补 1，不是"一天攒一次、回来一次抽十次"。
3. **保底先判后抽**。`GUARANTEE_N = 5`：第 5 次**先**判保底**再**抽，否则第 5 次仍可能落空，
   "保底"就成了假承诺。顺序反了是这类逻辑最常见的 bug。
4. **机会不进任何可见计数器**。PRD §4.4 原写"不给发现机会，否则变成悬空数字" —— 落地形态绕开了这个
   担心：家长端只有一个开关，孩子端看不到"我还剩几次"，所以它不会变成可炫耀的资源。

## 筛选改造的分层口径（容易改错）

`total / earned / percent / complete / recent / closest` 一律走**全量**，只有 `sections` 走筛选结果。
否则搜出 3 枚就变成"已获得 2 / 3"，看起来像突然丢了 25 枚成就。
另：**剪影卡不参与关键词匹配**——搜到 3 枚就等于确认隐藏成就存在，直接破坏隐藏机制；
但按状态 / 来源筛时照常保留（那是用户在主动浏览范围，不构成泄露）。

## 文档侧：裁决变更要留痕

`prd-v1.3-achievement.md` 的"不做"表里，被推翻的行**原文保留 + 划线 + 加 §2.2.1 变更记录**，
不做静默改写；`system_design-v1.3.md` §11 同一行同步标注。理由：旧裁决读起来仍要能看懂
**当时为什么那样判断**，否则后来人（包括未来的我）会以为这个决定没被认真想过。

# 追加 · V1.4 PRD 四项裁决落定（commit `8718d00`）

用户回答了 PRD §8 的四个问题，最要紧的是第一条：**家庭墙要跨设备，但方式是备份导出/导入，
且导入不得影响已有进度** —— 不是云同步。

- **根因**：现有 `importUserData(json, 'merge')` 对 `settings` 是 `db.settings.put(s)`（**整键覆盖**），
  而 `achievements` 恰好存在 settings 里 → 把备份搬到另一台设备会把**目标设备的成就墙抹掉**。
  这不是"少同步一次"，是丢数据。所以"跨设备"这条需求的真实内容 = **重写合并语义**，不是加同步通道。
- **合并口径**（PRD §P0-3c）：成就取并集（`unlockedAt` 取更早、`repeatCount` 取更大）；
  进度/错题**整行胜**（比 `lastReviewedAt` / `lastWrongAt`，**不做字段级合并** —— 否则造出
  "进度取自 A、复习次数取自 B"的怪行，`shouldAdvanceSchedule` 会误判）；打卡/每日统计逐字段 max；
  全局设置**本机优先**。唯一可自动化判据是**单调不减**（AC-P2-11）。
- **档案上限 4** 推翻了"切换时隐藏"的软上限：隐藏档案 = 数据蒸发，比报错难查。改为报错 + 引导"先导出再删"。
- **打印按小组分页**：M8 / G7 / B8 / E5 四页（`CATEGORY_ORDER` 顺序），组内不跨页，空组跳过，
  超容量续页页码不重编；导出图片与打印**共用同一套分页**（两套排版就是两套不一致的种子）。
- **表达式留 V1.5**：V1.4 schema **不预留 `expr` 字段** —— 预留一个永远报错的字段只会让家长写出无效配置。
- 顺手修了 prd-v1.3 §2.2.1 里指向 v1.4 的章节号（昨天写成 P2-x，实际是 P0-x）。
- 基线不变：单测 2129 / playwright 77（本轮纯文档，未跑 e2e）。

# V3.0 里程碑 · M1–M5（今日闭环 / 自适应 / 家长可行动 / 数据可信）

日期：2026-10-30
范围：系统能力迭代，不含新学习包（用户明确「下学期还早，不急」）。

## 一句话

把"打开 App 看到一堆推荐"改成"今天有 6 件事，做完就结束"，并把数据安全从
"记得手动导出"升级成"每天自动拍快照 + 导入后自检对账"。

## M1 · 今日任务队列

- `core/plan/dailyPlan.ts`（纯函数）+ `dailyPlanService.ts`（IO）
- 四类候选：到期复习 / 待攻克错题 / 弱项 / 新学；配额 `review .5 / mistake .25 / weak .15`
- **关键设计：新学不可饿死** —— 先扣 `newReserve`，配额基数用 `workBudget`，三轮填充。
  单纯按优先级贪婪填充会把 24 题全花在旧账上，孩子永远学不到新单元。
- 目标口径两套（题量 / 时长），**切换不重排**（只改分母，已完成项不能丢）
- 队列**当天冻结**（`builtAt` + 日期），否则每做完一项顺序就变
- 会话串联复用 `TopicDetail` 的 `?session=&limit=`，不重写 `QuizEngine`

## M2 · 自适应难度

- `core/plan/adaptive.ts`；档位来自 `metadata.difficulty`（基础/提高/挑战）
- 起始档取 BKT 掌握概率（≥.85 挑战 / ≥.6 提高），连对 3 次 +1 档、连错 2 次 −1 档
- 选题目标档 → 低一档 → 低两档 → 高一档 → 高两档，**永远凑够 limit**
- 技术裁决：**换挡只作用于"下一次练习"**，不在会话内插题（那要改 QuizEngine 核心循环）
- ⚠️ 踩过的坑：难度最初写成 `computed(() => levelOf(progressOf(...)))`，每答一题
  `progress` 变化 → 重算 → `selectSessionQuestions` 结果变 → `questions` 数组被换掉而
  `currentIndex` 不动 → **第 1 题变成另一道题**（Q=1+1 提交后显示 Q=3+3）。
  修法：`frozenLevel` 在 `initPracticeProgress` 里一次性冻结。

## M3 · 错因归类

- `core/mistake/errorClassify.ts`：7 种信号（空作答 / 多空部分对 / 漏单位 /
  数字错位 / 顺序颠倒 / 英文拼写 / 无关）
- **只给证据，不写库**：家长点「采纳」才 `onCauseChange`（尊重 `mistakeCause.ts` 的既有裁决）
- 判定顺序踩过两个坑：
  - `48` vs `4.8` 被判相等 → `squash()` 必须**保留 ASCII 小数点**
  - `15174` vs `15147` 被判"顺序颠倒" → **数字错位判定前移**，并补"数字全用上但位置错"分支
- 多空"部分正确"必须用**严格相等**，`includes` 会让「被减数」≈「减数」

## M4 · 数据可信

### 自动快照

- `core/backup/autoSnapshot.ts`：键 `backup:snapshots`（设备级），保留 7 份，同日跳过
- `AppShell.onMounted` 空闲时 `requestIdleCallback(takeSnapshot, { timeout: 8000 })`
- 恢复 = **合并**（走 `previewImport`/`executeImport`），不是回滚：只补回被删的，
  不覆盖本机更新的行
- 自我嵌套防护：`EXPORT_EXCLUDED_GLOBAL_KEYS` + `GLOBAL_NEVER_MERGE` 两处都排除

### `cardCompletions` 进备份契约

**推翻了 V1.4 的"不进备份"决定**（原注释：便利标记、可自动判定重建）。
改口理由：M4 把「换机后标记不丢」写进验收，而手动标记**无法从备份重建** ——
自动判定只能判"全都学过且没错题"的卡，家长手动点绿的往往是"这个单元口算过了"，
那是家长的判断，不在任何数据里。

改动点（缺一处就断链，且**不报错**）：

1. `core/backup/types.ts`：`Bundle.cardCompletions`（必填）/ `BackupV2.profiles[].cardCompletions?`（可选）
2. `core/backup/bundleIO.ts`：`dumpLocal` 逐档案 `where('profileId')` 读；导出带上
3. `core/merge/mergeCardCompletions.ts`：纯并集，key = `kind\0packageId\0targetId`
4. `core/merge/mergeBundle.ts`（折叠 + 计划）、`applyMergePlan.ts`（写入，无守卫 —— 不覆盖）
5. `importOrchestrator.bundlesFromV2`（老备份缺字段 → `[]`）、`routeBackup`（**可选**校验）
6. `syncManager.guardRemoteBundles` 行级 pid 校验 + `db/index.ts` 注释改口
7. `tests/helpers/fakeDexie.ts` 新增该表（`POST_V5_INDICES` —— 不污染 v3/v4/v5 历史快照）

备份文件里字段**必须可选**：改必填等于把用户手里所有历史备份判成"文件已损坏"。

### 换机迁移自检

- `core/backup/migrationCheck.ts`（纯）+ `migrationCheckService.ts`（IO）
- 五项：包 / 进度 / 错题 / 徽章 / 标记
- **判据是"不少于"而不是"相等"**：合并是并集，在用的设备 `actual > expected` 属正常，
  只有 `less` 报警。写成"相等"会让每次正常导入都变红，家长很快学会忽略它。
- `packages` 恒为 `n/a`（备份按设计不含包），不阻塞结论
- ⚠️ 类名坑：`` :class="`is-${verdict}`" `` 生成 `is-n/a`，`/` 会被 CSS 解析器当选择器
  语法（`Unexpected token '/'`）。改成显式 `verdictClass()` → `is-na`。

### `executeImport` 使今日队列失效（两模块交缝）

M1 的队列是当天冻结的；导入改变了进度全集，必须失效。原先只有**导入学习包**
（`importService.afterPackagesChanged`）做了这件事，**备份导入没做** ——
症状："导入了但今天没任务"，无任何报错。
修法：失效动作下沉到 `core/backup/importOrchestrator.executeImport`（所有导入/恢复的唯一入口），
动态 `import()` + try/catch 吞错。

## 学到的

1. **跨模块的断链不会自己发声**。M1/M4 各自的单测全绿，但"导入后今日页不重排"
   只有端到端跑一遍才暴露。里程碑收尾必须有一条**贯穿主路径**的 e2e。
2. **守恒的失败是"漏搬且不报错"**。所以：老格式字段一律可选 + 形状错误必须拒收
   （静默当空数组是更坏的选择）；合并新增的每一张表都要走"四处同步"清单。
3. **告警的判据要选能长期为真的一面**。"相等"在并集语义下必然长期为假，
   于是告警退化成噪声。选 `>=`，只对 `less` 报警。
4. **`Partial<T>` 展开会把必填字段变回 `T | undefined`**，对象字面量里
   `...over` 之后必须显式收口（或把赋值放到展开之后）。

## 二、裁决（**别再改回去**）

1. **规则只有 `manual-check` | `counter`，不预留 `expr`**（AC-P2-2）。表达式要配沙箱，V1.5。
2. **`customChecks` 是 per-profile，`achievement:customPacks` 是 global**。包是家里资产，
   勾选是这孩子的输入。勾选与解锁记录**分开存**（输入 / 输出），混存会导致停用再启用后
   「没勾过却已解锁」。
3. **`added` 必须是净新增**，另给 `retained` / `provided`，恒等式
   `provided === added.length + retained`。只用一个 `added` 时升版会把保留的卡算成新增，
   UI 的「将新增 N 枚」变成「重复导入一批」的误读。**改文案救不了，必须改数据结构。**
4. **跨包同 id 必须拒**（`E_ID_OTHER_PACK`）：`UnlockedRecord` 按 id 全局存、不带 packId，
   两个包同 id 会**静默**并成一张卡。判据取 `preview.conflicts`（同 packId 的旧版已被排除，
   否则升版会被误伤）；看**全部**已装包含已停用（停用不解锁记录，重新启用就串卡）。
5. **导入即启用**；升版保留原有 `enabled`/`enabledAt`（顺手「重新导入就启用」会悄悄打开
   一个家长特意停用的包）；回滚只退一版。
6. **停用/回滚不动 `customChecks:<pid>` 与 `achievements:<pid>`**（AC-P2-3/4）。

## 三、踩坑与判据

- **`manual-check` 的 `check` 不能依赖 `ctx`**，且要用构建 def 时捕获的 `checked` ——
  这样 `check()` 与 `measure()` 必然同源。否则卡只显示进度、永远不解锁。
  推论：**勾完必须重建 defs 并重跑 `syncAchievements`**，`settle()` 一次搞定。
- **`syncAchievements(ctx, now, extraDefs)` 的 extraDefs 放第 3 个参数**，故意如此，
  好让 `syncAchievements(ctx, extra)` 被 tsc 拦下。
- **自定义 defs 不并进 `ACHIEVEMENTS`**：那是内置 28 枚的唯一真相，混进去污染
  `missingTaxonomy()` / `MEASURABLE_IDS`。
- **`totalCount` 必须加 `customCount`**，否则解锁自定义卡后显示「已解锁 30/28」。
- **`mergeSettings` 从 `switch` 改成 `Record<ProfileScopedBase, …>` 登记表**：
  原来无 `default`，新键落进去返回 `undefined` → 下游当「本机缺失」→ 静默不合并，
  2580 条测试全绿却没人发现。现在加键由 tsc 报 TS2741 兜底。
- **`customChecks` 本版明确 SKIP 不合并**：`planMerge` 是纯函数、看不到 `db.packages`，
  计划阶段无法判断本机有没有那个包 —— 盲写勾选是「结构上不可能判对」。
  V1.5 要真合并，必须把本地包 id 集合传进 `planMerge`，光加规则不够。
- **注释/文档不要写死键数**（「8 个分片键」）。加第 10 个键时必然腐，且没有测试能发现。
  一律写「`PROFILE_SCOPED_KEYS` 里登记过的键」。

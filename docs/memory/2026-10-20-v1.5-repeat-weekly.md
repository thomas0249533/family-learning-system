# V1.5 · `repeatable: 'weekly'` 实施记录

> 日期：2026-10-20 · 裁决：**周从周一开始**（用户 2026-10-20 定）
> 前置：V1.4 · B6 只落了 `repeatCount` 字段与合并规则，写入侧刻意不递增

## 一、做了什么

`repeatCount` 从"只写不涨"变成"真的会涨"，范围**只有一枚**：

| 成就 | 周期 | `holds` 判据 |
|---|---|---|
| `streak-7`（一周不断） | 周一起算的一整周 | `effectiveCurrent(streak) >= 7` |

内置其余 27 枚**不声明** `repeat`，`repeatCount` 恒为 1。理由：它们的判定是累计型
（掌握 N 个、攻克 M 道、连对 K 题），条件一旦为真永远为真，"再达成一次"没有语义。
给它们加周期只会变成噪声。

## 二、唯一的正确性关键：`holds` 必须非单调

`streak-7` 的 `check` 是 `bestStreak = max(longest, current) >= 7` —— **单调**：
一旦连续 7 天，哪怕之后躺三个月也永远为真。

拿它当重复判据的后果：每过一周 `repeatCount` 就 +1，孩子躺平也照样「第 37 次」。
所以 `RepeatRule.holds` 单独给一个**非单调**谓词：`effectiveCurrent`（当前连续天数，
断两天以上归零；"昨天打过今天还没开始"仍算数，这是既有的宽限期）。

反向验证过：把 `holds` 改回 `bestStreak`，`tests/repeat-weekly.test.ts` 里
「下一周没坚持住 → 不涨」立刻变红，改回来又绿。**这条断言有判别力，不是摆设。**

## 三、周键为什么不用 `YYYY-Www`

用 `W<那周周一的日期>`，例如 `W2026-10-19`。

- ISO 周号在年边界要跨年换算（2026-12-28 是 `2026-W53` 还是 `2027-W01` 取决于口径），
  算错了**不会报错**，只会把某一周静默并到隔壁；
- 周一日期定宽、可直接字符串比大小（合并取"较晚"、结算判"是否同周期"都靠它），
  日志里也一眼能看出是哪一周；
- 前缀 `W` 是为了不和 `unlockedAt` 的日键混淆 —— 两种键同时存在于同一条记录里。

`mondayOf()` 用 `new Date(y, m, d - back)` 构造而不是 `setDate()`：跨月/跨年交给运行时
（`new Date(2026, 0, 1 - 5)` 正确落到 2025-12-27），也不碰时区。

## 四、三步闸门（顺序不能换）

```
① prev.lastRepeatPeriod === undefined  → 只落基线，不计数       （升级路径）
② prev.lastRepeatPeriod >= 本周键      → 跳过                   （同周期幂等 + 时钟回拨）
③ repeat.holds(ctx, now) === false     → 跳过                   （这周没真的做到）
④ 否则 repeatCount + 1，锚点更新为本周键
```

- **① 为什么必须存在**：旧记录没有锚点，我们无法判断"这一周是否又做到了一次"
  （可能是从解锁起一直保持，也可能昨天刚续上）。宁可晚一周开始计数，
  也不要在升级当天让所有老用户凭空多出「第 2 次」——那种"我什么都没做就多了"的
  观感，比少记一次糟得多。
- **②** 顺带兜住"系统时间被调回过去"：锚点更晚就什么都不做，等时间追上来。
- **④ 之外一律不写库**：`syncAchievements` 每次路由跳转都会跑，不能每次都落盘。
  写的条件从"记录条数变了"改成"条数变了 **或** `changed` 标记"——
  重复计数不改变条数，只看 length 会漏写。

## 五、存储与合并

`UnlockedRecord.lastRepeatPeriod?: string`（周键，幂等锚点）。

合并方向必须与 `repeatCount` 配套，两条都取 max：

| 字段 | 规则 |
|---|---|
| `repeatCount` | 取**较大** |
| `lastRepeatPeriod` | 取**较晚** |

只取 count 不取 period 就会出现：本机本周已计入（3 次 / W43）+ 远端上周旧备份（2 次 / W42）
→ 合成"3 次 + 锚点 W42"，合并后第一次结算发现"本周还没记过"，同一周又 +1 变成 4 次。
**这条写进了 `tests/repeat-weekly.test.ts` 的端到端用例。**

`normalizeRepeatPeriod` 严格到形状（`^W\d{4}-\d{2}-\d{2}$`）：这个值参与字符串比较，
大小写或形状不对的脏值不会报错，只会让比较结果永远偏向某一侧。

## 七、没做的（明确划线）

1. **自定义成就包不支持声明 `repeat`**。B3 的 JSON schema 里没有这个字段，
   家长自建的卡永远只记 1 次。要开放就得连"家长怎么描述一个非单调谓词"一起设计
   —— 那是表达式沙箱的活，不是加个布尔开关。
2. **`daily` 口径没做**。「今日之星（单日 ≥20 题）」是最典型的"每天都能再做一次"，
   但用户裁决的是 weekly，且 daily 会让计数一个月涨到 30（印记失去分量）。
   要做的话 `RepeatPeriod` 加一个 `'daily'`、`localDayKey` 当时周键即可，闸门逻辑不用动。
3. **PRD §P2 原文是"已解锁的成就再次达成 → 记一次"**，实现收窄成"只有 streak-7、
   按周计"。这是有意的偏离：原文那句按字面实现会虚涨（见 §二），
   范围收窄是唯一不虚涨的落法。

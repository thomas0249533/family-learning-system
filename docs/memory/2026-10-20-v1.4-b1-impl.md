# 2026-10-20 V1.4 B1 实施：档案底座

## 交付范围
v4 schema + 三段式迁移 + `currentProfileId()` 门面 + 写入端收口 + settings 键分片 + 切换 UI + 上限 4。
提交：`2823527`（feat 主体）/ `12454a7`（新门禁）/ `04e4581`（测试）。

## 已定裁决（后续别改回去）
- **`profileId` 必填**（`ProgressRecord` / `MistakeRecord` / `ExamSessionRecord`）：靠 TS2741 兜写入端，本轮实测抓到 4 处漏写。
- **旧复合索引直接删掉**：`[packageId+knowledgePointId]` 等保留即「跨档案串数据且不报错」，删掉反而让漏改的调用点当场抛错。新索引一律 `[profileId+...]` 前缀。
- **未 init 时 `currentProfileId()` 返回 `'default'`**（不是抛错）：启动前物理上没有用户交互可选，抛错只会让 2100 条测试都要先造档案。
- **`examSessions` 必须一起分片**（PRD 漏了）：否则老二在模考页看到老大成绩，撞「不做排行」红线。
- **档案上限 4 时不做「切换时隐藏」**：隐藏 = 数据人间蒸发，改为新建按钮禁用 + 文案提示；删除只删条目不删数据行，提示先导出备份。
- **`profileId` 生成用时间戳+随机**（`p_<base36>_<4位>`），不用递增序号 —— 两台设备各自建到 `p2` 会撞成一个 id 对应两个孩子。
- **v4 迁移不删旧 settings 键**：既留退路，也是「迁移成功」的证据。

## 两个非显然的实现细节
1. **unknown settings 键的幂等闸门要双证据**：只判 `endsWith(':default')` 会漏掉第三方本来就叫 `xxx:default` 的键（漏搬且无告警 = v4 最怕的事）。现实现是 `endsWith(后缀) && existing.has(父键)`（`migrateV4.ts:146`）。残留歧义：迁移前就同时存在 `foo` 与 `foo:default` 时按副本处理，两个都留、只报 `foo`。
2. **门禁只管读不管写**：`READ_OP` 正则只抓 `toArray/where/filter/count/clear/orderBy/each/offset/limit/reverse`；`update/add/put` 不需要 profileId 条件，第一版连写也拦导致 31 处误报。判定时把连续 6 行拼成逻辑语句，否则 `profileId: pid,` 那行会让整个访问点「通过」。

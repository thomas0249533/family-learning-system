## 需求的由来

用户上传《KET学习规划表（PU3+PU4＋冲刺）.pdf》（`content/KET/`），指出「前面 58 天是 PU3」，
要求把这两部分（单词、句型）做成学习包，并提示可以参考「58 天打卡」这种形态。

## 包结构（`content/ket-pu3-58d/`）

- `packageType: 'daily'` → 学习中心「每日一练」组，卡片元信息自动显示「58 天 · 每天 N 个板块」
  （`PackageCard.vue` 的 `dailyMeta` 取 `units.length` 与 `units[0].topics.length`）。
- **58 个 unit = 58 天**；每天两个板块：`单词默写`（`english.vocab` 模块，可进词语背记）
  + `句型`（`english.grammar` 模块）。
- 复习日（Day 20 / 39 / 58，PDF 里只有「复习 1-3 单元」这类文字）没有新词，改成
  **从前 3 个单元确定性抽 10 个词做混听写**；Day 38（只有口语要求、无词汇段）同样处理。
- 成品：629 词 / 91 句型 / 760 题。

PDF 抽取的坑（都已逐条显式修，不做启发式）：

| 现象 | 例子 | 处理 |
| --- | --- | --- |
| 丢空格粘连 | `intheair` / `bequiet` / `dressup` / `tookphotos` / `inthemiddle` | 显式映射表还原 |

## 分发：从「导入 10 个 zip」到「导入 1 个」

用户提出「修学习包时候会出现很多个包，选择起来很麻烦」。拆成两件事解决：

### 1. `npm run build:all` — 全库合集

`scripts/build-all-lpkgset.ts` 把 `content/*/_set.json` 覆盖的**所有包**合成
`content/all-packages/all-packages-set.lpkgset.zip`。

- ID 前缀仍按 `packageId`（与逐集合打包一致）→ 合集里的题与单独导入的题 ID 完全相同，
  进度不会断也不会重复。
- 包内缺失的集合级字段用**它自己那个集合**的值补齐（`math-4-up-rjb` 的 9 个包就没写 `term`），
  合集级 manifest 只做兜底 —— 结果与「单独导入该集合」一致。
- 实测：65 包 / 4537 题 / 1.62 MB。

### 2. `npm run check:lpkg` — 导入前自检

`scripts/verify-lpkgset-zip.ts` 对任意 `.lpkgset.zip` 复演 `importPackageSet` 的第 3/4 步
（建全局 ID 池 → 逐包 `normalizePackage`），E008/E009/资产缺失在这里就能拦下。
`build:lpkgset` 成功只代表「压出 zip 了」，不代表「App 能导入」，这是两件事。

### 3. 两个批量弹窗加「全选」（V4.0 并入）

包一多，`发现新学习包` / `修复题库` 默认「一个都不勾」就得逐个点。
各加一个全选复选框（带 `indeterminate` 半选态），**默认仍是不勾**（安全语义不变）。
`tests/e2e/content-update-bulk.spec.ts` 钉死：默认 0 且禁用 → 全选 3 → 再点归零。

## e2e 的沙箱坑（这轮踩到两次，务必记住）

1. `--trace=on` 时 trace 写 `C:\tmp\...\recording.network` 报 `EPERM`，
   **整条用例被记成 failed，但断言其实是绿的**。
2. Playwright 启动会清理 `test-results/`，被本机 safe-delete shim 拦成
   `SAFE_DELETE_BULK_GUARD_ERROR`，同样记成 failed。

可靠跑法：`npx playwright test --trace=off --output=<全新目录>`（`--output` 指向不存在的目录，
就没有「删旧产物」这一步）。判定失败时先看错误行是不是 `browserContext.close` /
`Tearing down "context"`，是的话不要改测试逻辑。

所以 `fsrs.ts` 存 UTC 不是待迁的债，是既定设计；真正被禁的是"拿 UTC 当日键"。

### 二、审计找到的真缺陷（1 个已修 + 1 个已焊死）

**① 真 bug（已修）：`src/core/motivation/achievementStory.ts` `dayOf()`**
`iso.slice(0, 10)` 把 UTC 全时刻截成本地该用的日串。`lastStudiedAt` / `wrongAt`
都是 `toISOString()` 写的，于是**本地 00:00–08:00（早起晨读窗口）学的记录，
UTC 日期部分属于前一天**，故事卡上"最近掌握 X · 昨天"。既有测试全是
`08:00Z` / `10:00Z`（UTC 午前）造数据，恰好每条都落在 UTC 日 = 本地日的
安全区，所以这个缺陷一直绿着——**测试数据的选择本身掩盖了 bug**。
修法：`localDayKey(new Date(iso))` + NaN 守卫。回归用例
`tests/achievement-story.test.ts`「★ 日期取本地日：清晨学的不能被算成前一天」
用**本地构造的瞬时**（`new Date(2026,9,19,0,30).toISOString()`），任何时区下
不会假红，只在正偏移时区真正锻炼边界（本机东八区）。先红后绿已取证。

**② 隐式契约（已焊死，未改语义）：`src/core/merge/mergeProgress.ts` `cmp()`**
"更晚者胜"用 `a > b` **字典序**比较 `progressRank`（`lastReviewAt ?? lastStudiedAt`）。
字典序 = 时间序**只在同格式下成立**。当前所有写入口都发 UTC 全时刻，所以正确
（200 组属性测试为证）；但一旦有人把写入口改成 `+08:00` 或引入日精度串，
混合格式下更早的瞬时可能胜出——**直接违反「单调不减」**。
处置：**没有顺手改 cmp 的语义**——日精度串（`'2026-02-01'`）解析成 UTC 零点后
与同时刻瞬时的相等语义怎么裁，是合并引擎的所有权决策，该由 E1-b 或合并 owner
带着测试决定，不该在审计任务里drive-by。改为：
- 新建 `tests/review-time-contract.test.ts` 把「写入口必须发 UTC 全时刻」钉成
  格式契约（谁改格式先在这里红，逼着他连 cmp 一起决策）；
- 在 `cmp` 上方写清耦合与改法。

## E2 · 智能错题重组引擎（已完成，引擎 + 测试，未动 UI）

**commit**：见文末。**先说结论：任务书里「进度必须回流原包」这个坑真实存在，
而且用反向验证实锤了——临时包一旦抄 KP 定义，`recordProgress` 的落库行
`packageId` 立刻变成 `special-weakpoints-auto` 自己，原包掌握度永不更新。**

### 一、最终设计：只引用、不声明（走了实例同构的那条路）

临时包 `special-weakpoints-auto` 的 topic / 题目通过 `knowledgePointIds`
**引用**原 KP id，自己的 `knowledgePoints` 保持 `[]`（唯一声明者留在原包）
→ `recordProgress(临时包, 原kpId)` 的 owner 解析回原包，进度落原行。

证据链（全部先读码后定稿）：
1. **线上既有同构实例**：`content/math-4-up-rjb/special-math-4-up-jiajiancheng.json`
   的 topics 引用 `unit-math-4-up-rjb-p5::kp-rel-*`，自己只声明 `kp-rel-101`；
2. **`ExamPanel.vue:276`**：入口包 = 自己，`handleAnswer` 对每个 kpId 调
   `recordProgress(entryPackageId, kpId)`，归一化在写入端统一做；
3. **`UnitList.vue:3/112`**：`examMode=true` 直接进 ExamPanel，**根本不调
   `resolvePackageUnits`**，题目渲染只认 `pkg.units[].topics[].exercises`；
4. **`QuizEngine.vue:787`**：作答 payload 的 `knowledgePointIds` 取自题目对象
   本身，不查包的 `knowledgePoints`。

即"包内 topic 引用未在本包声明的 KP"在全链路（渲染 / 导航 / 回流）都友好。

### 二、任务书/计划书被实例修正的两条

1. **`dependencies` 不空，列源单元包**（任务书勘误、计划书原文都是"必须为空"）：
   实例写 `dependencies: ['unit-math-4-up-rjb-p5']`；且
   `resolvePackageUnits.ts:63` 对 `deps.length === 0` 的 special 包提前返回、
   丢来源信息。照实例写。
2. **"基于 0 个单元"的真实位置**：不是 `resolvePackageUnits` 报错，而是
   `PackageList.vue:106` 的 `v-if="sourceUnitIds?.length"` —— 缺了只是**不显示**
   那段文案（examMode 包连 `resolvePackageUnits` 都不走）。铁律照写，
   但严重性与任务书描述不同。

### 三、选题规则（`weakpointsEngine.ts`，常量集中可调）

- 主池：`needsReview(level)` 且（错因 ∈ {knowledge, timeout, misread}
  **或** `wrongCount ≥ 2`）。careless 连续失败也进主池——总在同一个地方摔倒，
  首先是没学会；mastered 一律不选。
- careless 混入配额：`round(主池入选数 × 0.2)`（`WEAKPOINTS_CARELESS_RATIO`），
  单卷上限 30（`WEAKPOINTS_MAX_QUESTIONS`，ExamPanel 按 10 题/卷切片）。
- 只有 careless、没有主池候选 → **空 selection 不成卷**（不让孩子练"粗心"）。
- 排序（确定性）：未掌握 > 部分掌握 → wrongCount 降 → wrongAt 降 → exerciseId 字典序。
- 跨学科：取主池候选最多的学科成卷（manifest 只能一个 subject，subject 闸门：
  跨学科归属一律判异常）；支持 `opts.subject` 显式指定。

### 四、成就不污染：查清的机制 + 无需排除的理由

逐个消费点查完，结论是**引用式设计下临时包结构性惰性，不需要任何排除逻辑**：

| 统计 | 吃什么 | 临时包的影响 |
|---|---|---|
| 掌握率（Home/Parent/Report） | `computeMasterySummary` 的 domain = 各包 `knowledgePoints` | kpCount=0 → 不进分母 |
| `mastery-half` | `Σ kpCount` | 同上，无 |
| `explorer-3/10`、`term-cross`、`senior-new`、故事卡"学过的包" | **progress 行的 packageId** | 回流后行落在原包，临时包从不出现 |
| `noPackages` 引导 | `ctx.packages.length === 0` | 只可能把 true 变 false，非污染 |
| 今日推荐 `rulesEngine` | `knowledgePoints.length === 0` 直接 skip | 无 |
| 弱项 `weakPoints.ts` | `canonicalizeProgressRows` domain | 无 |
| 备份 | v2 按设计不含 packages | 无 |

测试背书：`tests/weakpoints-engine.test.ts` 对 **全部 25 个 `MEASURABLE_IDS`**
逐个断言"带/不带临时包 `progressOf` 相等"，外加 `computeMasterySummary`
整体相等。另外 `isInternal: true` 让包不进 `PackageList` 分组（E3 定入口）。

### 五、安全阀：归属解析失败的错题永不入卷

KP 无唯一 owner（歧义/零候选/跨学科/包已删）→ 该行跳过（计入 `skippedCount`）。
理由：入卷后 `recordProgress` 会把进度落到临时包自己头上——正是要避的污染。
宁少一题，不要一张会写错数据的卷。

  返回 `{ generated, questionCount, primaryCount, carelessCount, skippedCount,

  UI 提示"暂无可重组的弱项"即可。

### 四、踩坑 ①：fullPage 截图 + sticky 头 + click 滚动 = 中缝伪影（红绿取证）

- 现象：`parent-weekly-card-light.png` 里 y≈1350 处出现一条白带，内容正是
  AppShell 的 sticky `.app-header`（"家长视图 / 1月15日·星期三"），

- 根因：Playwright 的 `click()` 自带 `scrollIntoViewIfNeeded`，点「生成周报卡片」

  "这是'点了按钮再截图'自带的确定性陷阱，不是页面 bug"。

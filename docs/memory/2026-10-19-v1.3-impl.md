## 二、最终落地的关键设计（与早期设计稿相反，别再改回去）

1. **`version(3)` 保留**，`stores` 与 v2 逐字符相同，只为拿 `upgrade()` 钩子。
   - 钩子永不 rethrow；失败两条路径：① 事务 aborted → 版本不推进 → 下次 open 重跑；
     ② 钩子返回但计划失败 → 写 `migration:v3={status:'failed',attempts}` → 启动 `recoverV3IfNeeded()` 补跑，**上限 3 次**。
2. **`ensureE1Migrated({orphanOnly:true})` 与启动补偿是两件事**：
   前者在**每次导入包 / 恢复备份之后**跑，**绝不写 `migration:v3`**（只写 `progress:lastRecovery`），零计划不起写事务。
   两者**共用一把单飞锁**。
3. **`resolvePackageUnits` 三段式**：自有 units 优先 → `unit/base` 到此为止（链式依赖不再漏上游）→
   `special/sprint` 按 `manifest.sourceUnitIds` 精确追加 → `term` 回退全量依赖。
   `manifest` 新增可选 `type` / `examMode` / `sourceUnitIds`，并导出 `packageTypeOf()`：
   **运行时 JSON 只写 `type`，`packageType` 是别名，手写 `??` 极易漏**。
4. **写入端归一化收口在 `recordProgress`**：第 1 参数语义 = **入口包**，落库 packageId 由归属解析决定。
   调用点不需要知道这件事 → 新增调用方结构上不可能再写错包。
5. **成就进度禁止缓存历史最大值**：`check(ctx) === (current >= target)` 是硬约束（7×28 组测试钉死）。
   未获得的 `percent` 上限 **99**（四舍五入会算出"满格没亮"）。
6. **成就结算触发在 `AppShell`**：watch（进度数组 / 错题数组 / 路由）+ 去抖 800ms。
   不做在 7 个做题点位（分散易漏）。toast 也挂在布局层。

## 三、本机踩坑（新增）

- **裸 NUL 字节**：`Review.vue` / `exportService.ts` / `system_design-v1.3.md` 中被写入了**真的 0x00**
  当键分隔符，git 因此把文件判成 binary（`git diff` 只显示 Bin）。一律改为显式 `\u0000` 转义。
  排查命令：`python -c "print(open(p,'rb').read().count(b'\x00'))"`。
- **`*/` 出现在块注释里会提前结束注释**：我在 `manifest.ts` 的 JSDoc 里写了 `content/*/packages/*.json`，
  其中的 `*/` 让后面的 `packages/*.json` 变成代码 → `TS7008 Member 'packages' implicitly has any type`。
  注释里不要写 `*/`（用 `content/<集合>/packages/...`）。
- **Playwright + IndexedDB**：`page.evaluate` 删库必须在 `goto` 之后（about:blank 下 SecurityError）；
  不能用 `addInitScript` 清 localStorage（每次导航都跑，会清掉"刷新后保持"的断言）。
- **e2e 截图写入**：`primitives.spec.ts` 会覆盖写 `docs/screenshots/ds/*.png`，沙箱下 `EPERM`。
  跑全量 e2e 需 `dangerouslyDisableSandbox`（环境限制，不是代码错）。

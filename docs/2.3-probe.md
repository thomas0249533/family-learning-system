- 精细化白噪音：`NoiseGenerator.ts`（V2.2 已建，`src/core/focus/NoiseGenerator.ts`）升级 `ConvolverNode`/新增音效属纯前端。

## 轨道 D · Tauri 自动更新 —— ⛔ 偏差（硬约束，需方案选择）

### 偏差事实
- `src-tauri/Cargo.toml` 现有依赖仅：`tauri`/`tauri-plugin-log`/`candle-*`/`tokenizers`/`reqwest`/`sha2`/`rfd`。**无 `tauri-plugin-updater`、无 `process`**（`Cargo.toml` 全文 grep 确认）。
- `src-tauri/tauri.conf.json` 无 `bundle.publisher` / `updater` / `plugins` 配置（仅 `bundle.targets: "all"` + 图标）。
- 任务单要求：`tauri-plugin-updater` + `process`、生成公私钥、`.github/workflows/release.yml`、前端静默检查。

### 为什么是偏差（与 V2.1 标记一致）
1. **Rust 侧改动 = 重新打包**：加 `tauri-plugin-updater` 须改 `Cargo.toml` + `tauri.conf.json` +（若走签名）`Cargo.lock`，触发 `cargo build --release`，实测约 **52 分钟**重编（V2.0/V2.2 已两次实测）。
2. **服务器基础设施缺失**：自动更新需要「签名私钥 + GitHub Releases/自建分发服务器」。当前无 CI Secrets、无发布管线；私钥按安全规范不得入仓、须手工放 GitHub Secrets。
3. **网络/CORS 边界**：WebView 内 `fetch` 受 CORS 限制（V2.2 I2-a 已坐实）；原生更新通道需 `tauri-plugin-updater` 插件本身（即上述 Rust 改动）。

### 方案选择建议（请主理人择一）
| 方案 | 描述 | 代价 | 推荐度 |
|---|---|---|---|
| **D-1 仅 UI 占位 + 手动检查**（降级） | 前端 `AppShell` 加「检查更新」按钮：拉取一个 GitHub Raw 的 `version.json`（带 `ACAO:*`，CORS 可通过），有新版本则提示「去官网下载新版」并给链接；**不做自动下载/重启**。不改 Rust、不改 Cargo.toml。 | 纯前端；复用 V2.2 的 `CatalogTransport` 可插拔模式；~0 重编。 | ⭐⭐⭐ 推荐先行 |
| **D-2 真·自动更新（全量）** | 加 `tauri-plugin-updater` + `process`、生成密钥、写 `release.yml`、前端静默下载重启。 | Rust 改动 + ~52 分钟重编 + 签名密钥 + CI Secrets + 发布服务器。单次任务体量大、跨安全边界。 | ⭐（需单开） |
| **D-3 暂缓** | 本版不做自动更新，V2.3 只发 A/B/C，自动更新单开到 V2.5 或独立基础设施任务。 | 0；但用户要的「丝滑更新」不在本版。 | ⭐⭐ |

**建议**：先走 **D-1**（纯前端、零重编、今天能合并），把「自动下载重启」作为 D-2 单开任务，待发布服务器/密钥就绪再做。D-1 与 V2.2 I2-a 的「联网校验」完全同构，可复用 `catalogService` 的 transport + 类型化错误。

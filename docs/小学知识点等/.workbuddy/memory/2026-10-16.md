### 【真根因】截图抖动的元凶是 **SMIL**，不是 CSS 动画
- 现象：`animations: 'disabled'` **两个 spec 都已加上**，但 `app-button-*` 两轮 md5 仍全不同。
- 探针实测（`n-base-loading__icon`）：`svgCount:1 / smil:1 / cssAnim:0`，且**同一页面加载内连拍两张就不同**。
- **结论**：naive-ui 的 loading 图标用 **SMIL（`<animateTransform>`）**；Playwright `animations:'disabled'` 只覆盖 CSS 动画 / CSS 过渡 / Web Animations API，**对 SMIL 完全无效**。
- **修法**：`tests/e2e/freeze-smil.ts` → `setCurrentTime(0)` 后 `pauseAnimations()`（只 `pauseAnimations()` 会停在当前时刻，而当前时刻本身就不确定）。两处 spec 共用同一模块（避免两份微妙修复漂移）。
- **实锤**：38 张截图连续两轮 md5 **全部一致**（实测 `animationsPaused:true / currentTime:0`）。
- ⚠️ 教训：**第一次比对用的是"修复前的旧字节"当基线，误报为仍抖动** —— 确定性验证必须比**修复后的两次运行**。

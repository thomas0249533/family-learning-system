## 1. TL;DR

1. 本轮是**增量**：28 枚成就的 id、语义、解锁判定 (`check(ctx)`) 全部保留，不推倒重来；只补三样东西——**可算的进度**、**可折叠的界面**、**全链路的实时结算**。
2. 现状最大的洞不是"成就太少"，而是**判得太晚**：`syncAchievements` 只在 `Home.vue` 的 `onMounted` 调一次，孩子答完题、复习完、考完试都不会解锁，必须回首页才结算。本轮把结算做成"学习一发生就结算"。
3. 分类不新增第二套体系：**M/G/B/E 仍是唯一分类**（已有用户解锁数据的语义锚点），方案原文的"系统核心/学科/坚持习惯/隐藏"降为**来源属性 `source`**，稀有层级 `tier` 由证据难度**静态派生**，二者都不进数据库 → **零数据迁移**。
4. 奖励只给**非物质的**：徽章、证据快照、解锁日期、连环点亮。不给积分、不给兑换、不给排行、不给概率。
5. 同批交付三项工程债：`recordProgress` 按 **(归属包, knowledgePointId)** 归一化（口径收窄、掌握率会变，属**预期修正**；跨包同名 kpId 不合并，见 §2.3）、判断题题干 markdown 表格、学习流程 e2e 回归网。

### 2.3 非目标 · E-01 不可行方案（含反例数据）

> 前提（已核对）：**主路径下 `knowledgePointId` 带包前缀、是唯一的**——用户实际导入的 zip 内 43 个包 / 472 个 kpId，每个只被 1 个包声明，**零重复、零跨学科冲突**。只有**裸 JSON 单文件导入**这条边界路径上 kpId 无前缀、才会同名。以下三种归一化方案仍**不得采用**：

| 不可行方案 | 为什么不行 |
|---|---|
| ❌ **按 `knowledgePointId` 全局去重** | 主路径（zip）下 kpId 已唯一，此方案**收益为零**；但在**裸 JSON 单文件导入**边界路径下 kpId 无前缀，`english-7-up-rjb` 的 `p1`~`p7` 会复用 7 个同名 id（各指不同知识点），还可能与语文包同名 → 去重会塌数据。**故仍禁止，作为边界保护**，而非主路径的主要手段。 |
| ❌ **把复合索引 `[packageId+knowledgePointId]` 换成单主键 / 给 `knowledgePointId` 建唯一索引** | 同上去重灾难：唯一索引会硬拒写入第 2 个包的同名 id，或强制覆盖，导致跨包互相污染。 |
| ❌ **用 `packageType`（term/daily/sprint/special）做归属包 tie-break** | 无数据依据：同名 kpId 在多包并存时，按类型挑"哪个包是归属包"是**随机拍脑袋**，会把进度随机串到错误的包。 |

**正确口径（产品硬约束）**：归属包 = **在自己的 `knowledgePoints` 数组里声明了该 kpId 的包**（这是**所有权声明**；`units` 只是引用 / 聚合视图，**不能**作为判据）。仅当该 kpId 能被**唯一一个**包声明时才归一化；**多候选（歧义）或零候选 → 保留原记录不动**。具体实现由架构师定稿，但"歧义即保留"是产品不可让步的约束。

> 为什么判据必须是 `knowledgePoints` 而非 `units`：`term` / `sprint` / `special` / `daily` 包的 `units` 是**聚合视图**（从 unit 包拼来），同一 kpId 会同时出现在它们的 units 里 → 产生 3–5 个候选、大量误判为"歧义"（实测 units 口径覆盖率仅 **49.7%**，最高频的 unit 入口只有 26% 能归一化）；而 `knowledgePoints` 声明口径覆盖率 **100%（898/898）**（去重前 1252 个 `(入口包, kpId)` 组合，剔除入口包 own units 与 deps units 重复引用同一 kp 的 354 行后剩 898）。代码里已有同语义实现：`TopicDetail.vue:399-407` 的 `ownerPackageIdOf` 扫的就是 `pkg.knowledgePoints`。

## 3. 用户故事

### 3.1 家长视角

1. 作为**家长**，我想在家长端看到孩子**具体**拿到了哪几枚徽章、分别在哪天，这样我夸的时候能说"你连续 7 天没断，这个不容易"，而不是干巴巴一句"真棒"。
2. 作为**家长**，我想知道孩子离下一枚还差多少（"还差 3 个知识点"），这样我能判断要不要提醒他再练 5 分钟，而不是盲目催。
3. 作为**家长**，我想确认这套东西**没有**用抽奖、倒计时、排名、付费来驱动我孩子，否则我宁可关掉它。
4. 作为**家长**，我想看到徽章背后的证据（哪 10 个知识点、哪 50 道错题），这样我能判断这枚徽章是不是"真学会了"。
5. 作为**家长**，我不想一进首页就被 28 张卡铺满屏幕，已获得的应该收起来，我要看的时候再展开。

### 3.2 学生视角

1. 作为**孩子**，我答完最后一道题就想立刻看到徽章，**不要**让我先退回首页才发现自己解锁了。
2. 作为**孩子**，我想看到"还差 3 个就拿到了"，这样我知道再练一会儿就有结果，而不是只有一个模糊的目标。
3. 作为**孩子**，我已经拿到的徽章可以收起来，别一直占着屏幕；我想回顾的时候一键全展开。
4. 作为**孩子**，隐藏徽章请保持惊喜，别提前告诉我条件是什么。
5. 作为**孩子**，我希望徽章是因为"我真的做到了"才给的，不是因为运气好抽到的。

## 4. 成就方案设计

### 4.1 分类体系（两套分类的映射 + 零迁移）

**结论：M/G/B/E 是唯一分类，不替换、不重命名、不新增第五类。**

方案原文的"系统核心 / 学科 / 坚持习惯 / 隐藏"本质是**来源（source）**，回答"这枚成就是从哪来的、能不能被 JSON 包扩展"；M/G/B/E 是**动机类型（motive）**，回答"这枚成就在奖励什么心理机制"。两者是正交维度，混成一套会丢失信息。

所以本轮给 `AchievementDef` 增加两个**只读派生字段**（在代码里由静态表推导，不写入 IndexedDB）：

| 新字段 | 取值 | 用途 | 是否入库 |
|---|---|---|---|
| `source` | `core` 系统核心 / `subject` 学科 / `habit` 坚持习惯 / `hidden` 隐藏 | 未来 JSON 包过滤、家长端筛选、导入冲突判断 | **否**（派生） |
| `tier` | `common` 常见 / `advanced` 进阶 / `rare` 稀有 / `hidden` 隐藏 | 卡片视觉层级（边框 + 星标）、排序权重 | **否**（派生） |

#### 映射表（28 枚逐条归属）

| 现有分类 | 数量 | 映射到 `source` | 说明 |
|---|---|---|---|
| **M 精熟目标** | 8 | `core` 2 枚（`first-step`、`perfect-kp`）+ `subject` 6 枚（`ten-kp`、`fifty-kp`、`hundred-kp`、`kp-300`、`subject-master-3`、`mastery-half`） | 入门锚点属核心；累计量与学科覆盖属学科 |
| **G 成长型思维** | 7 | `core` 4 枚（`mistake-first`、`review-20`、`patience`、`streak-master`）+ `subject` 2 枚（`mistake-cleaner`、`mistake-cleaner-50`）+ `hidden` 1 枚（`comeback`） | 错题机制是产品内置 → 核心；规模化攻克属学科证据 |
| **B 行为塑造阶梯** | 8 | `habit` 5 枚（`streak-3/7/30/60/100`）+ `core` 1 枚（`daily-20`）+ `hidden` 2 枚（`early-bird`、`night-owl`） | 连续天数即坚持习惯；单日题量是一次性行为 → 核心 |
| **E 探索** | 5 | `subject` 5 枚（`explorer-3`、`explorer-10`、`type-collector`、`term-cross`、`senior-new`） | 探索的对象是内容资产（包 / 题型 / 学期 / 学科） |

汇总：`core` 7 · `subject` 13 · `habit` 5 · `hidden` 3 = **28**。

#### 迁移说明

1. **用户数据零迁移**：`source` / `tier` 不落库，只在 `AchievementDef` 静态表里声明。已解锁记录（`{id, unlockedAt}`）不需要改动，旧记录照常匹配。
2. **唯一的数据结构变更**：`UnlockedRecord` 增加**可选**字段 `evidence?: string`（≤40 字，解锁瞬间固化）。旧记录没有该字段 → 已获得卡不显示证据行，**不补算、不伪造**（补算出来的"证据"已经不是当时的证据）。
3. **语义不得漂移**：任何调整 `source` / `tier` 都属于"展示层变更"，但**任何调整 `check()` 或 `desc` 都属于"语义变更"，本轮禁止**。
4. 若未来接 JSON 包：`source` 变成包内必填字段（对应原文的 `category: subject/habit/hidden`），内置 28 枚作为 `core` 包；本次的静态表就是未来 schema 的对照基准。

### 4.2 稀有层级规则（由证据难度决定，不用概率）

#### 层级判定规则（按优先级，自上而下命中即停）

| 优先级 | 判定条件 | 层级 | 证据含义 |
|---|---|---|---|
| 1 | `hidden === true` | **隐藏** | 元认知 / 时段彩蛋，发现前不泄底 |
| 2 | 目标值 ≥ 50 **或** 连续 ≥ 30 天/次 **或** 掌握率门槛 ≥ 50% **或** 需覆盖 ≥ 3 个学科 | **稀有** | 迁移 / 耐力 / 深度 |
| 3 | 目标值 5–49 **或** 连续 5–29 天/次 **或** 需跨学期 | **进阶** | 稳定性 |
| 4 | 其余（目标值 ≤ 4 且单一维度） | **常见** | 入门确认 |

> 补充条款：**"首次发生"类成就（`senior-new`）即使涉及换学科，也归「常见」**——它奖励的是"迈出去"，不是"走得远"。层级衡量的是证据强度，不是事件的新奇度。

#### 为什么不用概率

1. **本轮没有随机**，层级若与概率挂钩就是空承诺；若未来上随机，方案原文已定死"池内等概率"。
2. **用概率表达价值 = 制造人为稀缺**，会把"学得好"偷换成"运气好"，直接违背六条不变量的第 3 条与伦理红线"不向儿童展示概率"。
3. **可解释性**：家长问"为什么这枚是稀有"，答案必须是一句人话（"因为要连续 30 天"），而不是"因为它出现率 3%"。
4. **可测性**：层级由静态规则算出，可以做穷举单测（28/28）；概率需要统计与调参，无法在 node 单测里验收。

#### 层级 → 视觉（仅消费既有 token，颜色不是唯一编码）

| 层级 | 边框 | 标记 | 底色 | 非颜色编码 |
|---|---|---|---|---|
| 常见 | 1px `--border-color` | 无 | `--card-bg` | 边框粗细 |
| 进阶 | 2px `--primary-color` | 右上角 1 枚 `★`（`--primary-text`） | `--card-bg` | 边框粗细 + 星标数量 |
| 稀有 | 2px `--success-color` | 右上角 2 枚 `★★`（`--success-text`） | `--success-soft` | 边框粗细 + 星标数量 + 底色 |
| 隐藏（已解锁） | 2px `--info-color` | 角标文字「隐藏成就」（`--info-text`） | `--info-soft` | 文字角标 |

> 儿童视图**不出现**"稀有 / 史诗 / SSR"这类字样，层级只通过边框、星标数量、底色表达，`aria-label` 里给一句中性描述（如"层级：进阶"）。家长视图可以显示文字。

### 4.3 解锁条件规则（保留谓词，另加进度；用一致性测试绑定）

**建议：保留 `check(ctx): boolean` 作为**唯一解锁真相**，不改成声明式 DSL；新增 `progressOf(id, ctx)` 纯函数作为**唯一进度真相**，二者用穷举一致性测试绑定。**

理由：

1. **改造成本 vs 收益不成立**：28 条谓词已经写好、已有单测覆盖，语义清晰。改成 DSL 需要写求值器 + 重写 28 条 + 处理边界（多条件与或、前置门槛），收益只是"JSON 可导入"——而 JSON 导入是 P2，本轮不做。
2. **双真相的风险必须用测试堵死**：谓词和进度若各写一遍，必然漂移。规则是——**对同一条 `ctx`，`progressOf(id).current >= target` 必须恒等于 `check(ctx) === true`**（隐藏成就与带前置门槛的成就单列用例）。
3. **声明式只做在数据层，不做在逻辑层**：`source` / `tier` / `target` / `unit` 这些**常量**是声明式的（静态表），判定逻辑仍是函数。这样既拿到了"规则表可读、可校验"的好处，又不引入解释器。
4. **为 P2 留接口**：未来 JSON 包的条件用 DSL 描述，内置 28 枚用 `check` 适配成同一种 `AchievementDef` 接口即可，不需要现在重构。

#### `progressOf` 的契约

```
progressOf(id, ctx) → { current: number, target: number, unit: string, kind: 'counter' | 'binary' } | null
```

- 返回 `null` 表示"该成就无法进度化"（仅隐藏成就未解锁时）。
- `current` 必须 **clamp 到 `[0, target]`**，不允许出现 `11/10`。
- 计算必须是**纯函数**：不读 db、不读 store、不碰 `Date.now()`（时间类由 `ctx` 提供）。放在 `src/core/motivation/achievementProgress.ts`，与 `@core/review/fsrs.ts`、`@core/quiz/judge.ts` 同级。
- **进度不落库**：每次渲染从同一次结算的 `ctx` 现算。理由：单机数据量小（千级），现算 <5ms；落库会带来"进度表 vs 解锁表 vs 实际数据"三份不一致，且错误数据会永久残留。

### 4.4 奖励定义

#### 给什么（全部非物质）

| 奖励 | 具体形态 | 兑现时机 |
|---|---|---|
| **徽章本体** | 图标 + 称号 + 一句描述（沿用现有 `icon/title/desc`） | 解锁即得 |
| **证据快照** | 一句话事实，≤40 字，如"已掌握 10 个知识点"、"连续学习 7 天（10/12–10/18）" | 解锁瞬间写进 `evidence`，此后**不随数据变化** |
| **解锁日期** | `YYYY-MM-DD`（本地时区，沿用 `localDayKey`） | 解锁即得 |
| **连环点亮** | 链内进度可见（"精熟之链 2/5"）+ 上一环旁显示"下一环：🌱 迈出第一步" | 解锁即得 |
| **回看权** | 进入"已获得"区，可折叠、可随时展开重看 | 永久 |

#### 不给什么（明确排除）

| 不给 | 为什么 |
|---|---|
| 积分 / 金币 / 经验值 / 等级 | 会立刻把"学习"变成"刷分"，且需要一套消费出口，滑向 P2/P3 |
| 抽奖次数 / 发现机会 | 本轮无随机；给了也没有消耗口，只会变成悬空数字 |
| 兑换（实物、特权、解锁新题库） | 触碰六条不变量第 1 条"不可购买"，且把家长拖进物质奖励谈判 |
| 排行榜 / 好友对比 / 公开稀有度 | 触碰伦理红线；家庭场景没有社交需求，只有比较带来的焦虑 |
| 限时 / 倒计时 / 每日必得 | 制造紧迫感，正是方案要剔除的"盲盒式焦虑" |
| 家长物质奖励模板（"拿到 10 枚换玩具"） | 过度理由效应：外部奖励会侵蚀内在动机，产品不该主动提供这个梯子 |
| 徽章附带功能特权 | 会让"没拿到"变成"用不了"，把激励变成门槛 |

一句话原则：**徽章只证明"你做过什么"，不兑换任何"你能得到什么"。**

1. **进度只对未解锁卡显示**。已解锁卡显示解锁日期 + 证据，不显示进度条（避免"10/10"这种无意义回放）。
2. **`current ≥ target` 但尚未解锁**是瞬时态（结算未发生的间隙）：文案降级为「已达标 · 正在确认」，不显示"还差 0 个"。结算链路必须保证这个状态 ≤1.5s。
3. `daily-20` 的 `dailyStats` 只保留最近 60 天：已解锁不受影响；未解锁时历史峰值会随窗口滚出而回落——这是可接受的（正常使用下解锁是即时的，不会拖 60 天）。
4. 隐藏成就即便已解锁，也**不补显示进度**，只显示"隐藏成就已解锁"标记 + 解锁日期。

**统计基元的语义变更（E-01 带来，必须预知）**

- `distinctPackages` 的计数键从「入口包」变成「归属包」：结构上界 **43 → 26**；但对只用 term / sprint 入口的家庭反而**上升**（例：一个 `sprint-english-7-up-final` 覆盖 7 个归属包，过去只算 1 个）。
- ⇒ `explorer-3` / `explorer-10` 会**变易**：做一次覆盖多归属包的模拟考可能直接从 1 跳到 ≥3、当场解锁 `explorer-3`。这是**真实行为变更，接受，不做补偿**（不调高门槛、不加前置）；但 QA 基线与进度文案必须按「归属包」计数。
- 其余基元不受影响：`masteredKp` / `masteryRate` / `masteredBySubject` 走 `computeMasterySummary`；`clearedMistake` / `streak` / `dailyStats` / `attemptedTypes` 与包归属无关。

## 5. 界面需求

### 5.1 信息架构

成就区仍位于**首页**（`Home.vue`「我的成就」section），**不新增路由、不新增导航项**（独立"成就图鉴页"列入 P1，见 §8）。

```
我的成就                                        [12 / 28]
────────────────────────────────────────────────────────
总进度条  ████████░░░░░░░░  43%
                                     [ 全部展开 / 全部收起 ]

▸ 已获得 (12)                                   ← 默认收起
    ├ 精熟目标 4 枚            ▸                ← 组级，跟随父区默认收起
    └ 成长型思维 3 枚          ▸

▾ 待解锁 (16)                                   ← 默认展开
    ├ 精熟目标  4 枚未得       ▾
    │    [卡片] [卡片] [卡片] [卡片]
```

- **分区（2 个）**：`已获得` / `待解锁`。
- **分组（每组 4 个）**：沿用现有 `M / G / B / E`，标签与图标不变（精熟目标 / 成长型思维 / 行为塑造 / 探索）。
- **排序**：组内「待解锁」按完成度**降序**（可进度化的按 `current/target`，二值型排最后，同分按既有定义顺序 `order`）。已获得组内按解锁日期**降序**（最近拿到的在前）。理由：孩子第一眼看到的是"马上能拿到的"，这是确定性的"可达性提示"，不是随机。

### 5.2 折叠交互规格

| 项 | 规格 |

#### 进度提示文案规则

设 `c = current`，`t = target`，`n = t - c`。

| 状态 | 文案模板 | 示例 |
|---|---|---|
| 已达成待结算 | `已达标 · 正在确认` | — |
| `c / t ≥ 0.8` 且 `c < t` | `就快拿到了 · 还差 {n}{量词}` | 就快拿到了 · 还差 2 个知识点 |
| `0 < c < 0.8t` | `已完成 {c}/{t} · 还差 {n}{量词}` | 已完成 3/10 · 还差 7 个知识点 |
| `c === 0` | `目标 {t}{量词}` | 目标 10 个知识点 |
| 事件型（`t === 1`，`c === 0`） | `完成一次即可解锁` | — |
| 事件型（`t === 1`，`c === 1`） | `已达标 · 正在确认` | — |
| 隐藏 | `达成后揭晓` | — |
| 前置门槛未满足（`mastery-half`） | `需先有 20 个知识点` | — |

**量词表**：知识点 → `个`；错题 → `道`；连续天数 → `天`；题量 → `道`；学习包 → `个`；题型 → `种`；学期 → `个`；学科 → `科`。

**文案红线**：
- 不出现"抽""概率""稀有""限时""错过就没了"。
- 不出现否定式催促（"你怎么还没拿到"）。
- 数字必须来自 `progressOf`，禁止前端另算一套。

### 5.4 空态与边界

| 场景 | 表现 |
|---|---|
| **0 枚解锁** | 不渲染「已获得」区（避免出现一个空壳分区）；总览条下显示一行引导：`还没有徽章。掌握第一个知识点，就能拿到第 1 枚。`；「待解锁」区照常展开 |

### 5.5 视觉与 token 约束（硬门禁）

1. **零新增色值**：新增样式只允许消费 `--primary-color` / `--success-color` / `--warning-color` / `--danger-color` / `--info-color` 及其 `-text` / `-soft` / `-light` 变体、`--band-*`、`--text-main` / `--text-sub` / `--text-muted`、`--border-color`、`--card-bg`、`--bg-color-hover`、`--radius-*`、`--duration-*`、`--ease-*`。
2. **文字色只能用 `--{tone}-text`**，`--{tone}-color` 只用于边框/背景/填充/图形。这是 `check:text-color` 的硬规则。
3. **不新增色相、不新增纹理资源**：层级差异靠边框粗细、星标数量、底色软填充表达。
4. 三道门禁必须全绿：`npm run check:hex`、`npm run check:text-color`、`npm run lint:styles`。
5. 深色模式：对比度 ≥ AA（正文 4.5:1、大字 3:1），`--success-soft` / `--info-soft` 上的文字必须是 `-text` 变体。

## 6. 链路需求

### 6.1 触发时机（要覆盖全部"会产生成就证据"的行为）

| # | 时机 | 位置 | 触发方式 | 说明 |
|---|---|---|---|---|
| 1 | 应用启动 / 进入首页 | `Home.vue` onMounted | 立即 | 保留现状，作为兜底 |
| 2 | 单题作答结算后 | `TopicDetail.vue::handleAnswer` / `handleWarmupAnswer` | **防抖 600ms** | 主链路，M/G/B 类主要来源 |
| 3 | 模拟考交卷 | `ExamPanel.vue::finalizeExam` | 立即 | **作答过程中不结算、不弹提示**，避免打断考试 |
| 4 | 错题攻克 / 标记掌握 | `Mistakes.vue` / `Review.vue` 提交后 | 防抖 600ms | G 类 |
| 5 | 复习完成 | `Review.vue` 每次提交后 | 防抖 600ms | G 类 |
| 6 | 背单词训练 | `VocabDrill.vue::writeProgress` 后 | 防抖 600ms | B/E 类 |
| 7 | 学习包导入完成 | `ImportWizard` 完成回调 | 立即 | 影响 `distinctPackages` / 掌握率分母 `total` / 学科覆盖 |

**不触发**：路由切换、页面重新可见、窗口 resize（避免无意义重复结算）。

### 6.2 机制建议（最终方案由架构师定）

1. **单一数据源**：新建 `achievement` store（Pinia，沿用现有 store 模式），持有 `records: UnlockedRecord[]`、`lastCtx`、`settledAt`。任何页面展示成就**必须读这个 store**，禁止各自 `loadUnlocked()`。
2. **单飞结算**：`settle()` 内部维护 `inflight: Promise | null`。并发调用复用同一个 Promise，保证"一次学习事件最多弹一次"。防抖窗口内的多次触发合并。
3. **ctx 组装集中一处**：`buildAchievementContext()` 唯一入口，从 `userDataStore` / `packageStore` / `loadDailyStats()` / `loadAttemptedTypes()` / `loadStreak()` 取数。任何调用方不得自行拼装（避免口径分叉）。
4. **先落库，后提示**：`syncAchievements` 写 `db.settings` **成功后**才把 `newlyUnlocked` 交给 toast 队列；写失败则不弹、不更新 `records`，下次触发重试。宁可不弹，不可弹了却没存。
5. **全局 toast host**：`<AchievementToast>` 从 `Home.vue` 移到 `AppShell.vue`（跨路由常驻，单实例），由 store 推入队列。`Home.vue` 删除本地实例与本地 `enqueue` 调用。
6. **跨页同步**：`Home` / `Parent` / `Report` 全部从 store 读。`Parent.vue` 保持**只读**（不加编辑、不加开关）。
7. **失败隔离**：结算异常一律 `try/catch` + `console.warn`，**绝不阻塞答题主流程**；异常不写入"已结算"标记，下次自然重试。
8. **进度更新**：进度不落库，由 `progressOf(id, store.lastCtx)` 渲染时计算。`lastCtx` 在每次结算后整体替换（不可变），保证 UI 与解锁判定同源。
9. **首次加载**：store `ensureLoaded()` 幂等；首页与家长端并行调用时只真正读库一次。

## 7. 工程债需求

### 7.1 `recordProgress` 写入的 `packageId` 未归一化为「归属包」

> ⚠️ **本节的关键约束：唯一键只能是 `(packageId, kpId)`。禁止按 `kpId` 去重、禁止给 `kpId` 建唯一索引。**

**现状（已核实）**：

- `recordProgress(packageId, kpId, ...)` 按 `(packageId, kpId)` 查找并写入，`packageId` 由**调用方传入的入口包**决定：`ExamPanel` 直接取 `dependencies[0]`（**确定写错**）；`TopicDetail` 主练习取路由里的 `packageId`（从 `UnitList` 进入时已切换为归属包，但路由可被直接构造）；`TopicDetail` 课前热身用 `ownerPackageIdOf`（**正确语义**）。⇒ 同一个知识点换个入口进来就可能写出第二条。
- **运行时数据（`.lpkgset.zip`）里 `kpId` 是唯一的**：43 个包、472 个被声明的 kpId，**每个只被 1 个包声明**，零重复、零跨学科冲突；english-7 的 p1–p7 在 zip 里全是带前缀的唯一 id（`unit-english-7-up-rjb-p1::kp-reading-001` … `p7::…`）。可当 QA 夹具的 48 行见 `docs/kp-id-ownership-english-7.md` §1。
- **"裸 JSON 单文件导入"路径存在同名不同义**：`content/english-7-up-rjb/*.json`（构建中间产物）里 p1–p7 各自定义同一套短 id（7 个 id × 7 包 = **49 行**，`kp-reading-001` 还被 `special-chinese-4-up-reading` 用作「梅雨潭」）。这条路径若不做前缀重写就会串数据；`scripts/lib/idRewrite.ts` 已有重写能力。
- **结论**：`kpId` 在 zip 路径"当前恰好唯一"，不是模型保证；裸 JSON 路径直接冲突。⇒ **唯一键只能是 `(packageId, kpId)`**，按 kpId 去重在任何一条路径上都不安全。本轮修的是**写入端传错了包**，不是主键。

**产品目标（一句话）**：

> 把写入 `progress` 的 `packageId` 从「学习入口包」归一化为「真实归属包」（**在自己的 `knowledgePoints` 里声明了该知识点的包**），使同一 `(归属包, kpId)` 只产生一条进度；同时修正专项 / 冲刺包写错 `packageId` 的现状缺陷。

**对用户的实际影响（不是洁癖问题）**：

1. **旧公式下掌握率虚高、甚至 >100%（现状）**：分母按包内 KP 条数累加、分子按"进度行数"。**只要某次学习写入了"入口包 ≠ 归属包"的行**，同一知识点就会被算两次以上。当前确定可复现的来源是 `ExamPanel`（见影响 5）；`TopicDetail` 课前热身已用 `ownerPackageIdOf`（正确语义），主练习用路由里的 `packageId`——从 UnitList 进入时它已被切换为归属包，但路由可被直接构造、后续新增入口无法保证。⇒ 仍需在**写入端统一收口**，不能靠每个调用方自觉。
2. **成就证据失真（现状）**：`masteredKpCount` 按行数计，重复行会让 `ten-kp` 这类低门槛成就提前达成。改用 `computeMasterySummary(...).mastered` 后虚高消除，但**若不修写入端，孤儿行会持续产生**（`orphanRecordCount` 只增不减），统计与复习都要长期背着垃圾数据。
3. **口径统一后这些行不会"自动变对"**：新公式会把无法归因的行隔离为孤儿、不计入分子——**这不是修复，只是止损**。要让记录真正被复习计划与统计消费，必须让它落到正确的 `(归属包, kpId)` 上。
4. **复习队列异常**：写错包时两种相反表现——能反查到 KP 就变成**重复复习卡**，反查不到就**直接丢记录**（影响 5）。
5. **该条进度静默丢失**：`ExamPanel.vue:266-269` 取 `deps[0]` 当 `packageId`。`sprint-math-4-up-final` 的 deps 是 `[p1,p3,p4,p5]` 却覆盖 `p6` 的知识点 → 写成 `(p1, p6KP)`；`Review.vue:151` 用 `findUnitByKnowledgePoint(p1, p6KP)` 反查，p1 里没有这个 KP → 返回 `null` → `continue`，**该条进度永远进不了复习计划**。

**产品口径**：

- 同一 **(归属包, knowledgePointId)** **只应有一条进度记录**；**跨包同名 kpId 不合并**（视为不同知识点，见 §2.3）。
- **归属包的判定语义（硬性）**：以「**该包的 `knowledgePoints` 里声明了该 kpId**」为准，**不要用 units 反推**——term / sprint / special / daily 的 units 是从 unit 包聚合/复制的，按 units 反推会得到 3–5 个候选，全库只有 49.7% 能唯一解析；按 `knowledgePoints` 声明判定则 100% 唯一（`TopicDetail.vue:399-407` 的 `ownerPackageIdOf` 已经是这个语义，可直接复用）。
- 裸 JSON 单文件导入路径：**导入时必须做 id 前缀重写**，重写后必须满足"每个 kpId 只被 1 个包声明"；不满足则拒绝导入（P2 的校验器负责，本轮只在 PRD 记约束）。
- **掌握率口径以 `docs/mastery-metric-definition.md`（已定稿）为唯一权威，本 PRD 不再自定义第二套公式**：统一调用 `computeMasterySummary(packages, progress)`；**分母** = `(packageId, kpId)` 去重后的知识点全集（函数内部再收敛"同 kpId 且 title 全同"的副本），**分子** = 其中状态为「已掌握」的 key 数；孤儿记录计入 `orphanRecordCount`、不进任何桶；`rate` clamp 到 `[0,100]`。
  > 作废声明：此前"分子只计已声明对、分母仍用 `Σ kpCount`"的写法**作废**，与定稿文档冲突。
- 修复后掌握率的变化**主要不是来自迁移**：可归因行只是被重写为归属包，分母与分子都不变，**迁移本身带来的变化应 ≈ 0**。真正会变的是两类：① 含「裸 JSON 单文件导入」历史包的库，Report 分母会从裸 kpId 去重展开为二元组（english-7 类包 7 → 49）；② 用户删除**单元包（归属包）**后，该单元 KP 同时退出分母与分子，「已掌握」数下降（旧表现是只掉分母、rate 反而升）；而删除 `term/sprint/special/daily` 等**聚合入口包**时，行本就挂在 unit 上，`mastered` / `total` / `orphan` 三项**全不变**。纯 zip 库应按「基本持平」验收，不得把「普遍下降」写进预期。
- 已解锁成就**不追回**（沿用"一旦解锁永不撤销"原则），但新判定一律基于合并后的数据。
- 不做全屏弹窗解释；在家长端「成就概览 / 学习报告」区块底部加一行脚注：`统计口径：同一知识点在同一个学习包内只计一次。`（常驻一行，不用一次性弹窗）。
- `orphanRecordCount` **只做诊断**（迁移日志/控制台），不进入家长端、不进入儿童端，避免家长追问"什么是孤儿"。
- 不设任何"口径缓冲"（例如"只统计学过的包作分母"）：那会让掌握率随学习进度单调趋向 100%，并让 Home / Report 的 `total` 彻底不可比，违反 AC-E1-2 的三处一致。若确需解释，只在**删除学习包**的确认弹窗按包类型分两句（**用户可见，写死**）：**聚合入口包**（term/sprint/special/daily）——「删除后不影响已掌握知识点的统计（它们归属各单元包）。」；**单元包**（unit）——「删除后该单元的知识点将不再计入掌握率。」——那是删除功能的说明，不是统计口径的特例。

### 7.2 判断题材料里的 markdown 表格

**现象**：`content/english-7-up-rjb/sprint-english-7-up-final.json` 的 `sprint-ex-023`（`type: "judge"`，4 个陈述）题干里有一段 GFM 表格：

```
| Day | Subject |
|---|---|
| Monday | English, math, PE |
...
```

当前渲染成**一行竖线**，孩子读不出课程表，题直接做不了。

**根因**（已核实）：`src/modules/core/QuizEngine.vue:318` 的 `renderQuestionText` 只做了 HTML 转义 + `replace(/\\n/g, '<br>')`——它替换的是**字面反斜杠 + n**，而 JSON 里的 `\n` 解析后是**真实换行**，所以真实换行既没变成 `<br>`，表格也没有任何解析。判断题切分（`splitJudgeStatements`）拿到的"材料"同样带着这段未处理的文本。

**需求**：题干支持**最小 Markdown 子集**——
1. 真实换行 → 换行（`<br>` 或 `white-space: pre-wrap`，二选一，工程定）；
2. GFM 表格（`| a | b |` + 分隔行 `|---|---|`）→ `<table>`；
3. 其余内容保持纯文本 + HTML 转义。

**不做**：图片、链接、HTML 标签、代码块、列表、加粗斜体。理由：题干是内容资产不是文档，子集越小，注入面和样式风险越小。

**验收标准**：

| # | 条件 |
|---|---|
| AC-E2-1 | `sprint-ex-023` 在**练习页、模拟考页、错题本**三处均渲染为 2 列表格（`Day` / `Subject`），5 行数据完整 |
| AC-E2-2 | 真实换行在题干中生效（连续两行文本不再挤成一行） |
| AC-E2-3 | 题干含 `<img src=x onerror=alert(1)>` 时按纯文本显示，不执行、不生成元素 |
| AC-E2-4 | 表格单元格内的 `\|` 转义正确（不误切列），空单元格渲染为空 `<td>` |
| AC-E2-5 | 表格在窄屏（375px）下不撑破卡片：表格容器可横向滚动（`overflow-x: auto`），页面本身不出现横向滚动条 |
| AC-E2-6 | 表格边框/表头底色只用 `--border-color` / `--bg-color-hover`，深色模式可读，`check:hex` 通过 |
| AC-E2-7 | 其余题型题干渲染零回归：抽查 ≥20 道不含表格的题，文本内容与改动前一致（可做快照断言） |

## 10. 待确认问题（需用户拍板）

1. **成就区留在首页，还是新开独立"成就图鉴"页？**
   本轮按"留在首页 + 两级折叠"设计（零路由变更、零导航改动）。若希望做成独立页，首页只留"已解锁 N/28 + 最近 3 枚"入口，则工作量与导航信息架构都要重估。

2. **「待解锁」区默认展开是否可接受？**
   默认展开意味着 0 解锁时首屏会出现 28 张卡（比现状略长，但有进度提示）。备选：默认只展开"完成度最高的 2 个组"，其余收起——更短，但规则更绕、孩子可能找不到某枚。**建议保持默认全展开。**

3. **掌握率口径统一后数字会变，家长端怎么解释？**
   分母改为 `(packageId, kpId)` 去重、分子去重并排除孤儿。**迁移本身几乎不改变数值**（可归因行只是换了 packageId）；只有两种真实变化：① 含裸 JSON 历史包的库，Report 分母会从裸 kpId 展开（english-7 类包 7 → 49）；② 删除**单元包（归属包）**后该单元 KP 退出统计；删除聚合入口包（term/sprint/special/daily）时统计不变。建议：不弹窗，只在家长端统计区块底部加一行常驻脚注「统计口径：按 (学习包, 知识点) 去重，同一知识点只计一次」。是否需要更醒目的说明（如首周一次性提示条）？

4. **e2e 的测试数据用哪种？**
   建议新增 `tests/fixtures/mini-package.json`（≤50KB，3 个知识点、6 道题、1 个单元）。备选：复用 `content/` 下真实包——更真实，但体积大、内容会变、断言语义脆弱。

5. **28 枚全部解锁后的处理？**
   建议：显示「全部收集完成」+ 隐藏待解锁区，不加新视觉、不做动画（留给 P1 的总结卡）。是否需要本轮就给一个"毕业"画面？

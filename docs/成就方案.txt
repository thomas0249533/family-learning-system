以下为《家庭学习系统 · 成就发现系统 v1.0 详细方案》，可直接作为 PRD/技术设计初稿。方案正式名称用“**成就发现**”，保留盲盒式惊喜感，但剔除付费、消耗性抽取、公开稀有度攀比。

---

# 一、方案定位与不可违背的原则

## 1.1 一句话定位
**学习行为产生“发现机会”，系统从“已够格”的未拥有成就中随机呈现一个；随机只负责惊喜时刻，不定义成就价值；稀有度只代表掌握深度/坚持时长，不代表抽中概率。**

## 1.2 六条不变量（后续所有迭代不得突破）
1. **不可购买**：发现机会不能付费、不能积分兑换、不能转让。
2. **不预告具体奖励**：学习前不承诺“学完必得稀有卡”；发现是后置惊喜。
3. **随机只发生在“已够格池”**：成就资格由真实学习事件判定，随机只决定此刻呈现哪一个。
4. **保底必出**：连续 N 次未出新，下一次必出未拥有成就；池空时明确提示“继续学习解锁更多发现条件”。
5. **JSON 导入不包含概率、价格、交易价值、排行字段**；导入包默认不启用，家长/教师预览后启用。
6. **视觉走 token**：成就卡不新增硬编码色值，复用现有语义色/`--band-*`/`--text-muted` 等；稀有层级用图标、边框、纹理、文字表达，不靠新色相。

## 1.3 教育心理学锚点
- **自主**：发现是可选支线，可积累后连续发现，可关闭随机退化为顺序解锁。
- **胜任**：稀有度绑定“连续正确、间隔复习达标、跨单元迁移、错题纠正、长期坚持”等证据。
- **归属**：家庭/班级内成就墙展示“学习故事与证据”，不做公开稀有度排行榜。

# 二、概念模型与主流程

## 2.1 主链路
```
学习事件 → 触发判定 → 成就资格(eligible) → 发现池
   → 用户点击“发现”（消耗1次发现机会）
   → 随机+保底 → 解锁成就 → 证据快照 → 图鉴/成就墙
```

## 2.2 核心概念
| 概念 | 定义 |
|---|---|
| **成就定义** | 一个可解锁的成就模板，含触发条件、层级、叙事、证据模板、视觉引用 |
| **成就资格 eligible** | 用户已满足触发条件但尚未被发现的成就 |
| **发现池** | 当前用户所有 eligible 且未拥有的成就集合 |
| **发现机会** | 由学习行为自然产生的次数，不可购买；有每日/每周上限与积累上限 |
| **发现** | 从池中随机呈现一个成就并解锁；受保底规则约束 |
| **证据快照** | 解锁时记录的事件 ID、统计值、时间窗口、掌握度版本，防止后续数据变化导致证据失真 |
| **图鉴** | 已发现成就的收集视图；未发现只显示“还有 N 个待发现”，不泄露隐藏成就 |

## 2.3 状态机
- 成就定义：`draft → active → deprecated`（导入包可禁用/回滚）
- 用户成就：`locked → eligible → discovered → pinned/archived`
- 发现机会：`earned → consumed`；保底计数器：`missCount`，出新后归零
- 重复成就：**v1 不做重复卡**；已拥有从池中移除。后续家庭赠送再做“故事卡/纪念印记”，不进入二级交易。

## 2.4 发现机会产生规则（建议初始值，可配置）
| 学习行为 | 机会 | 限制 |
|---|---|---|
| 完成一个学习单元 | +1 | 同一单元每日只计一次 |
| 完成到期复习 | +1 | 同一知识点每日只计一次 |
| 纠正错题并通过验证 | +1 | 同一错题每日只计一次 |
| 连续学习天数里程碑 | +1 | 每周最多 2 次 |
| 每日上限 | 3 次 | 每周上限 10 次 |
| 积累上限 | 5 次 | 超出不再累积，避免囤积焦虑 |

> 发现机会不消耗积分/货币；只消耗“次数”。家长可调低上限或关闭随机。

# 三、成就分类与稀有度设计

## 3.1 四类成就
| 类型 | 来源 | JSON 可导入 | 约束 |
|---|---|---|---|
| **系统核心成就** | 产品内置 | 否 | 覆盖入门、首次完成、基础习惯，保证基础体验 |
| **学科成就** | JSON 包 | 是 | 必须声明 `subject` 与 `trigger.event` |
| **坚持/习惯成就** | JSON 包 | 是 | 必须含时间窗口与频次上限，防刷 |
| **隐藏/彩蛋成就** | JSON 包 | 是 | 必须是“正向意外”，不得惩罚性条件；发现后才显示详情 |

## 3.2 稀有层级：由证据难度决定，不由概率决定
| 层级 | 证据含义 | 示例 | 视觉表达（走 token） |
|---|---|---|---|
| **常见** | 入门确认 | 首次完成某单元 | `--border-color` + 常规图标 |
| **进阶** | 稳定性证据 | 连续 5 次正确/完成 3 次间隔复习 | `--primary-color` 边框 + 进度纹理 |
| **稀有** | 迁移/耐力证据 | 跨 3 个单元综合正确、连续 14 天坚持 | `--success-color` 边框 + 星形图标 |
| **隐藏** | 元认知/创造性证据 | 纠正特定错误模式、非常规解法 | 发现前灰显；发现后 `--info-color` 标识 |

**关键规则**：发现池中默认**所有 eligible 等概率**；层级不改变抽中概率，避免人为稀缺。家长端可查看池大小、保底进度、最近发现记录；不向儿童展示“概率营销”。

# 四、触发条件与证据模型

## 4.1 标准化学习事件
所有模块发出统一事件，成就引擎只消费事件，不直接读组件状态。建议字段：
`eventId`、`profileId`、`eventType`、`subject`、`module`、`itemId`、`knowledgePointIds`、`outcome`、`durationMs`、`attempt`、`timestamp`、`offline`、`schemaVersion`。

事件类型至少覆盖：`unit_completed`、`quiz_completed`、`question_answered`、`review_completed`、`mistake_corrected`、`vocab_drill_completed`、`exam_completed`、`streak_milestone`。

## 4.2 条件声明式 DSL（JSON 中只允许声明，不允许脚本）
支持条件：`event`、`subject`、`module`、`count`、`windowDays`、`consecutive`、`accuracyThreshold`、`distinctKnowledgePoints`、`spacedReviewCount`、`mistakeCorrectionCount`、`masteryThreshold`（后续接 FSRS/掌握度）。**禁止**任意脚本、外部请求、概率字段。

## 4.3 证据模板
每个成就定义 `evidenceTemplate`，例如“连续 14 天完成英语跟读”“在 3 个单元中综合正确率 ≥ 90%”。解锁时生成证据快照，成就卡显示“获得条件 + 我的证据”，而不是稀有度标签。

## 4.4 幂等与防刷
- `eventId` 去重；同一 `itemId + eventType + 日` 只计一次。
- 条件必须含时间窗口或频次上限；无上限的计数类成就需评审。
- 离线事件排队同步，按 `timestamp` 与 `eventId` 幂等合并。
- 异常检测：短时间大量事件、时钟回拨、重复包导入，进入待审核但不直接封禁。

# 五、JSON 成就包规范

## 5.1 包结构字段
| 字段 | 说明 |
|---|---|
| `schemaVersion` | 包格式版本，必填 |
| `packageId` | 命名空间，成就 ID 为 `packageId:achievementId` |
| `version` | 包版本，支持升级/回滚 |
| `name/author/description` | 元信息 |
| `subjects` | 适用学科 |
| `achievements[]` | 成就定义数组 |
| `resources` | 仅允许预定义图标名/纹理名，不携带色值、脚本、外链 |

成就定义字段：`id`、`title`、`description`、`category`（subject/habit/hidden）、`rarityTier`（common/advanced/rare/hidden）、`trigger`、`evidenceTemplate`、`narrative`、`prerequisites`、`cooldown`、`maxUnlocks`、`enabledByDefault=false`、`visualRef`（只引用 token/icon 名）。

## 5.2 明确禁止字段
`probability`、`weight`、`price`、`cost`、`tradeValue`、`ranking`、`limitedTime`、`externalUrl`、`script`、`colorHex`。导入包不得设置抽取概率或视觉色值。

## 5.3 导入流程
```
选择文件 → 解析 → schema 校验 → 语义校验（事件白名单/条件可评估/频次上限/文本安全/资源白名单）
→ 预览“将启用哪些成就、哪些与现有冲突” → 家长确认启用 → 写入审计 → 可回滚
```
默认不自动激活；支持按学科/类型选择性启用；导入审计记录包 ID、版本、时间、启用范围、回滚点。

## 5.4 校验失败处理
结构错误拒绝导入；语义可疑（无时间窗口、条件过宽、隐藏成就惩罚性）标记“需人工复核”，不进入 active。

# 六、数据模型建议

| 实体 | 关键字段 |
|---|---|
| `achievement_package` | packageId、version、schemaVersion、status、importedAt、enabledScopes |
| `achievement_def` | 全局 ID、category、rarityTier、trigger、evidenceTemplate、visualRef、status |
| `achievement_progress` | profileId、achievementId、counter、windowStart、lastEventAt、state |
| `user_achievement` | profileId、achievementId、discoveredAt、evidenceSnapshot、pinned、archived |
| `discovery_counter` | profileId、availableChances、missCount、dailyEarned、weeklyEarned |
| `learning_event_log` | eventId、profileId、eventType、payload、timestamp、offline、dedupKey |

本地优先存储；多孩子档案按 `profileId` 隔离；导出/备份包含成就与证据快照；删除档案需二次确认。

# 七、UI/UX 方案

## 7.1 页面与入口
- **成就图鉴页**：已发现成就网格；未发现显示“还有 N 个待发现”；隐藏成就发现前灰显不泄底。
- **发现入口**：学习完成页非阻塞提示“获得 1 次发现机会”；可立即发现、可积累；不自动跳转。
- **发现动画**：短、可跳过、尊重 `prefers-reduced-motion`；动画不是奖励强度来源。
- **成就卡**：标题、叙事、获得条件、我的证据、发现时间、层级用图标+文字+边框表达。
- **家庭成就墙**：只展示已发现成就与学习故事；不显示稀有度排行榜；可置顶。
- **家长端**：开关随机发现/仅顺序解锁；查看发现池大小、保底进度、最近记录；导入/启用/回滚 JSON 包；设置机会上限。

## 7.2 可访问性
对比度 AA；颜色不作为唯一编码；键盘可操作；动画可关闭；文本长度限制；图标有 alt。

## 7.3 与主题 token 的约束
成就卡视觉复用 `--primary-color`、`--success-color`、`--info-color`、`--warning-color`、`--band-*`、`--text-muted`、`--border-color`；不新增硬编码色值。若需层级纹理，用 CSS 图案/图标引用，不引入新色相。

# 九、度量、伦理与验收

## 9.1 度量指标
发现机会获取/消耗、eligible→discovered 转化、保底触发率、随机模式关闭比例、导入包启用率/回滚率、发现后 2 周学习事件变化、挫败反馈、家长满意度。**不把发现次数与学业成绩考核绑定**。

## 9.2 伦理红线
不做付费抽取；不做限时稀有营销；不向儿童展示概率；不做公开排行；隐藏成就不得惩罚；发现动画不制造“再抽一次”的紧迫感；家长可完全关闭随机。

## 9.3 验收标准
- P0：核心成就确定性解锁，图鉴可用，无随机。
- P1：发现+保底可用；关闭随机可退化为顺序解锁；连续 N 次未出新必出。
- P2：JSON 包通过 schema/语义校验，默认禁用，家长可预览启用/回滚，审计可查；包中无概率/色值/脚本。
- P3：家庭成就墙仅家庭组可见，无公开排行。
- 全局：组件无新增硬编码色值；事件幂等；离线同步不重复计数。

# 十、分阶段落地与任务清单

| 阶段 | 任务 | 产出 | 依赖 |
|---|---|---|---|
| **P0 确定性图鉴** | T-A01 学习事件标准化与幂等；T-A02 成就定义/进度/图鉴 UI；T-A03 核心成就集 | 无随机，验证收集结构吸引力 | 现有模块事件；T01 token |
| **P1 发现与保底** | T-A04 发现引擎（池、等概率、保底、机会上限）；T-A05 发现 UI/动画/开关；T-A06 家长端发现设置 | 随机发现可用，可关闭 | T-A01/A02 |
| **P2 JSON 导入** | T-A07 schema/语义校验器；T-A08 导入预览/启用/回滚/审计；T-A09 导入包示例与文档 | 家长可扩展成就 | T-A02；T-A07 |
| **P3 家庭归属** | T-A10 家庭成就墙/故事分享/置顶；T-A11 重复纪念印记（可选，不做交易） | 归属感增强 | T-A05/A08 |
| **持续** | T-A12 指标与伦理评审；T-A13 与 FSRS/掌握度对接 | 数据驱动迭代 | T12 |

**建议初始参数**：保底 N=5；每日机会上限 3；每周 10；积累上限 5；池空提示不消耗机会。所有参数家长可调低，不可调高到无上限。

# 十一、风险与待决策点

| 风险 | 对策 |
|---|---|
| 过度理由效应 | 后置、不预告、可关闭随机；观察“为抽而学”信号 |
| 刷取 | 事件幂等、时间窗口、频次上限、异常检测 |
| 导入包质量 | 语义校验+人工复核+默认禁用+回滚 |
| 稀有度误解 | 卡面显示证据而非概率；家长端解释；无公开排行 |
| 动画干扰 | 可跳过、减少动画、不制造紧迫感 |

**待决策**：保底 N 的最终值；是否允许积累机会；是否允许家庭内赠送；隐藏成就提示程度；是否向家长展示池内具体未解锁成就；P3 是否做重复纪念印记。

---

**总结**：先做 P0 确定性图鉴验证收集结构，再做 P1 发现+保底，最后开放 P2 JSON 包。整个系统的“随机”只发生在已够格池中，稀有度由学习证据决定，JSON 只扩展内容不扩展概率，视觉严格走现有 token。这样既保留盲盒的惊喜与收集感，又不把学习动机抵押给概率。

先给结论：这轮主题重构的设计方向是对的，但它解决的是“颜色一致性”和“历史硬编码清理”，还不是“设计系统可演进性”与“学习系统核心能力”的终点。后续建议分四轮走：**主题收尾与质量门禁 → 设计系统 2.0 → 学习闭环增强 → 工程化与平台化**。不要跳过质量门禁直接做新功能，否则 240 处硬编码会回潮，双源漂移会继续。

---

## 一、现状判断：设计成熟度与主要风险

### 做得好的地方
- **Token-First + Facade 思路正确**：`theme.scss` 是 CSS 唯一源，`variables.scss` 做 SCSS 门面，`palette.ts` 做 JS 数值源，`App.vue` 只消费。
- **T01–T05 拆分合理**：T01 先建令牌基础设施，T03/T04/T05 并行收敛，T02 把 T1/T2 耦合处理，符合依赖顺序。
- **有防漂移意识**：`palette-consistency.test.ts` 锁 `palette.ts ⇄ theme.scss`，比纯人工核对强。
- **有治理雏形**：§8.5 新增 token 白名单、§8.9 全局不变量、§8.8 验证准入，这些应继续保留并自动化。

### 关键风险
| 风险 | 说明 | 后续动作 |
|---|---|---|
| **双源只是被测试锁住，没有消除** | `palette.ts` 与 `theme.scss` 仍是两套真相，测试只能防漂移，不能防设计意图分叉 | 中期做单源生成 |
| **无视觉回归测试** | 颜色重构没有像素基线，人工核对不可持续 | 引入 Playwright 截图矩阵 |
| **`fontSizeMap` 双缩放** | naive-ui 字号 + 根字号 rem 同时生效，用户调字号可能双重放大 | 列为 P0，单独迭代修复 |
| **硬编码会回潮** | 组件内禁止 `#hex`/`rgba(数字)` 目前靠约定 | Stylelint + CI 强制 |
| **项目无 git** | 备份只读不能替代版本控制，无法回滚、分支、协作 | 最高工程风险，建议立即本地 git 初始化 |
| **JS 运行时取色分散** | echarts、PDF、内联样式各自取色 | 建 `useThemeTokens` / `useChartTheme` / PDF 固定浅色 |
| **PWA 与 Tauri 更新策略未分端** | `PWAUpdateBar` 在 Tauri 下可能无意义或与自动更新冲突 | 分端策略 |
| **可访问性未覆盖** | 学科色、深色对比度、焦点、减少动画 | 设计系统 2.0 纳入 AA 目标 |

## 二、四轮迭代路线

### V1.1 主题重构收尾与质量门禁（P0）
**目标**：T01–T05 交付后，确保“不漂移、不回潮、可回归”。

关键交付：
1. 完成 T01–T05，并冻结 §8.5 白名单。
2. **视觉回归基线**：Playwright 截图矩阵——浅/深 × 首页/报告/搜索/复习/错题/家长/学习子页/模块 × 关键状态。
3. **防回潮门禁**：Stylelint 禁止 `views/`、`modules/`、`components/` 内出现 `#hex`、`rgba(数字)`，白名单仅 `theme.scss`、`variables.scss`、`palette.ts`。
4. **修复 `fontSizeMap` 双缩放**：统一为单一缩放源，或明确 naive-ui 与根字号只保留一个。
5. **JS 取色统一**：图表、PDF、内联样式走主题服务；PDF 固定浅色，打印样式 `@media print` 固定浅色。
6. **分端更新策略**：PWA 用 Service Worker 更新条，Tauri 用原生更新，不重复提示。
7. **App.vue 拆分**：抽 `ThemeProvider`、`AppShell`、`buildThemeOverrides` 纯函数，避免 App 膨胀。

退出标准：`vue-tsc` 零错误、101 + 一致性测试全绿、视觉回归通过、零硬编码扫描通过、人工浅/深核对无旧 indigo/`#1e1e1e` 残留。

### V1.2 设计系统 2.0（P1）
**目标**：从“颜色 token”升级为“完整设计系统”。

关键方向：
1. **单源生成**：当前双源 + 一致性测试可短期接受。中期推荐 `tokens.ts` 为唯一源，构建期生成 `theme.scss` 的 CSS 变量与 `palette.ts` 的 JS 对象。一致性测试降级为生成校验。
2. **三层 token**：primitive（原始色板）→ semantic（primary/success/bg/card）→ component（button-primary-bg、card-header-bg）。当前只有 semantic，组件级 token 可减少 naive-ui 与自定义组件不一致。
3. **UI 基元封装**：`AppButton`、`AppCard`、`AppBadge`、`StatCard`、`SectionTitle`、`ProgressBar`、`EmptyState`、`PageHeader`，统一色值、圆角、间距、焦点态。
4. **多主题与可访问性**：浅/深/跟随系统/高对比/护眼；WCAG AA 对比度、`focus-visible`、`prefers-reduced-motion`、色盲友好。学科色深色下需变体或容器底色，避免不可读。
5. **组件文档与预览**：Histoire 或 Storybook，展示 token、浅深、状态、a11y。
6. **Token 生命周期**：提案 → 评审 → 加入白名单 → 双源同步 → 测试 → 文档 → 废弃。

### V1.3 学习闭环增强（P1）
**目标**：从“做题页面”升级为“学习系统”。

关键方向：
1. **领域模型统一**：课程/单元/知识点/题目/错题/复习计划/掌握度，统一 ID、schema 版本、时间戳、软删除。
2. **间隔重复算法**：从简单复习升级到 FSRS 或 SM-2，记录难度、稳定性、可提取性。
3. **错题归因**：知识点、粗心、时间、难度，生成弱项画像。
4. **掌握度与推荐**：知识点掌握度、能力雷达、弱项优先推荐。
5. **报告与家长端**：周报/月报、趋势、目标、奖励、多孩子档案、屏幕时间、内容权限。
6. **搜索增强**：全文索引、拼音、模糊、高亮 token 化。

### V1.4 工程化与平台化（P2）
**目标**：可维护、可发布、可扩展。

关键方向：
1. **Git + CI/CD**：立即 `git init`，当前状态 initial commit；CI 跑 `vue-tsc`、单测、视觉回归、Stylelint、build。
2. **E2E 与组件测试**：Playwright 覆盖关键链路；Vitest + happy-dom 组件测试。
3. **性能预算**：首屏、路由懒加载、naive-ui 按需、echarts 按需、虚拟列表、字体子集、包体预算。
4. **离线与同步**：IndexedDB/本地文件、Service Worker 版本化、冲突解决、导入导出、备份恢复。
5. **Tauri 安全**：CSP、allowlist、更新签名、窗口主题、启动闪白。
6. **国际化**：若英语模块需要，UI 多语言与内容分离。

## 五、关键决策点

1. 是否接受引入构建脚本，把 `tokens.ts` 作为单源生成 CSS/JS？
2. 是否允许深色下学科色微调，以换取可读性？
3. 是否立即引入 git + CI？项目无 git 是当前最大工程风险。
4. 是否支持多孩子、云同步、家长通知？这会反向影响数据模型。
5. 是否采用 FSRS？比 SM-2 更现代，但需要历史数据。
6. 可访问性目标是否定为 WCAG AA？
7. PWA 与 Tauri 是否继续双端并行？更新策略必须分端。

## 六、验收指标建议

- 零硬编码：组件层 `#hex` / `rgba(数字)` 扫描为 0。
- 一致性测试：`palette.ts ⇄ theme.scss` 全绿。
- 视觉回归：浅/深关键页面截图通过。
- 可访问性：关键文本对比度 ≥ 4.5:1，焦点可见。
- 性能：首屏 < 1.5s，包体预算内。
- 字号：无双重缩放。
- 更新：PWA/Tauri 不重复提示，成功率可观测。
- 数据：schema 迁移可回滚，导入导出可用。
